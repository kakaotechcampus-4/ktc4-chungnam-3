# 저장 목록과 커서 페이지네이션

`feat/addtest`의 별도 실제 API 컬렉션이다. 기본 CI 실행 목록에는 추가하지 않는다.

## 검증 범위

- 새로운 A·B 회원의 빈 목록
- A가 서로 다른 영상 3개를 순서대로 저장한 뒤 최신 저장 순서와 목록 필드 확인
- B는 A의 첫 영상 하나만 저장해 같은 콘텐츠와 개인 저장물의 소유권을 구분
- `size=2`의 첫 페이지·마지막 페이지 및 페이지 간 누락·중복 확인
- 같은 첫 페이지 재조회와 `size=1` 전체 순회
- 최대 페이지 크기 조회
- A의 커서를 B가 사용해도 A의 저장물이 노출되지 않는지 확인
- 세션 없음·임의 세션 차단
- 0·음수·최대값 초과·문자·소수 size와 잘못된·빈·201자 cursor 거절
- 잘못된 조회 후 기존 목록 유지
- 커서 기준 행을 삭제한 뒤에도 기존 커서로 남은 페이지 조회
- 마지막 페이지 데이터를 삭제한 뒤 기존 커서로 빈 페이지 조회
- A의 저장 삭제가 같은 영상을 저장한 B의 목록·상세에 영향을 주지 않는지 확인
- 모든 개인 저장물 삭제와 로그아웃

41개 요청 파일이며, `size=1` 순회의 2회 반복을 포함하면 정상 실행 시 총 43회 호출한다.

## 준비와 실행

Bruno에서 이 폴더를 컬렉션으로 열고 `local` 환경을 선택한다.
`environments/local.bru`의 `shortsUrl1`, `shortsUrl2`, `shortsUrl3`에 **서로 다른 공개 Shorts 영상 3개**를 넣는다.
기존 기본 영상 `FyXT_7huLds` 하나만으로는 여러 저장물·페이지를 검증할 수 없다.
입력 형식과 중복은 첫 로그인 전에 검사하므로 같은 영상의 공유 URL만 바꿔 넣으면 실행을 막는다.

현재 서버는 우분투 백엔드와 PC의 SSH 터널이 연결된 `http://localhost:18080`을 사용한다.
기본 페이지 크기 20, 최대 크기 100, 요약 최대 길이 200을 기준으로 하므로 서버 설정이 다르면 환경 값도 맞춘다.

컬렉션 전체를 실행한다. `size=1` 반복은 Runner/CLI에서 동작하며 개별 Send만으로 전체 순회를 입증할 수 없다.

```powershell
# 저장소 루트에서
cd test/bruno-save-list
New-Item -ItemType Directory -Force reports | Out-Null
bru run --env local --noproxy --reporter-junit reports/list.xml --reporter-skip-all-headers --reporter-skip-body
```

환경 파일에 공개 URL을 저장하지 않으려면 CLI의 `--env-var shortsUrl2=... --env-var shortsUrl3=...`로 전달할 수도 있다.
세션과 개인 저장물 ID는 실행 중 변수만 사용한다. 요청·응답 헤더와 본문을 제외한 보고서는 Git에서 제외한다.

## 분석 비용과 검사 경계

새 영상 저장은 실제 분석을 시작할 수 있으므로 이미 분석된 서로 다른 영상 3개를 사용하는 것이 좋다.
이 컬렉션은 목록·정렬·커서의 계약을 검사한다. 분석 완료를 기다리거나 SUCCESS를 요구하지 않는다.
분석 중·부분 실패·실패도 정상적인 목록 상태이므로 제목·요약의 null과 분석 상태 변경을 허용한다.
정렬과 페이지 이동의 기준인 저장물 ID·저장 시각은 유지돼야 한다.

커서는 직접 만들어 정상값처럼 사용하지 않고 서버가 발급한 값을 재사용한다.
서로 다른 회원이 같은 커서를 사용했다는 이유로 오류를 요구하지 않는다. 응답이 해당 회원의 데이터로 제한되는지가 기준이다.

이 3개 데이터로 기본 크기 20에서의 잘림, 동일 저장 시각의 UUID 보조 정렬, 동시 저장·삭제 중 스냅샷 일관성,
분석 품질을 검증했다고 판단하지 않는다. 별도 시드·동시성 테스트 또는 기존 JUnit으로 확인할 항목이다.

정상 종료 시 A의 3개와 B의 1개 개인 저장물을 삭제하고 로그아웃한다. 계정과 공용 콘텐츠는 남을 수 있다.
강제 종료·설정 오류·중간 요청 실패 시 일부 데이터가 남을 수 있으므로 기존 공용 회원 대신 매번 새 회원을 사용한다.
