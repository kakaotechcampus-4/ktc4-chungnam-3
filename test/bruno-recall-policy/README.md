# 위치 이벤트 차단 정책

5개 폴더를 각각 새로운 회원과 이벤트 UUID로 실행한다. 이전 시나리오의 쿨다운에 의존하지 않는다.
202 응답만으로 통과시키지 않고, 읽기 전용 DB 확인 도구로 실제 조건·실행·알림 건수를 검증한다.

| 폴더 | 차단 조건과 대조 검사 |
| --- | --- |
| 01-withdrawn | 저장·트리거가 존재하고 기존 실행이 없는 회원의 위치 동의만 철회. 차단 확인 후 재동의하면 같은 이벤트가 실행돼야 함 |
| 02-other-member | A가 저장한 실제 장소로, 위치 동의만 한 B가 전송. B와 A 양쪽에 실행이 없어야 함. B도 같은 장소를 저장하면 같은 이벤트가 실행돼야 함 |
| 03-deleted-save | 실행 이력이 없는 회원의 저장물 삭제 후 트리거가 사라졌는지 확인. 이벤트 차단 후 같은 장소 재저장 시 실행돼야 함 |
| 04-stale-event | 동의·저장·트리거는 정상이고 기존 실행이 없는 상태에서 허용 시간보다 1분 오래된 이벤트 전송. 시각을 현재로 바꾸면 같은 이벤트가 실행돼야 함 |
| 05-cooldown | 정상 이벤트로 실행 한 건을 먼저 생성. 기존 이벤트와 다른 새 UUID·현재 시각으로 전송해도 새 실행이 없어야 하며, 기존 실행 ID·알림 건수도 유지돼야 함 |

## 실행

기존 `test/bruno-recall`의 실행기와 DB 확인 도구를 재사용한다. API 주소·DB·SSH 설정 방법은 해당 README와 같다.

```powershell
$env:RECALL_SSH_TARGET = 'ubuntu@서버주소'
$env:RECALL_SSH_IDENTITY = 'C:/본인경로/서버접속.key'
node test/bruno-recall/run.mjs --policy
```

기본 API 주소는 `http://127.0.0.1:18080`이고, DB는 Docker 컨테이너 `remembrall-db`의 `remembrall`이다.
Bruno CLI가 표준 전역 설치 경로에 없다면 `BRUNO_CLI_JS`에 `bin/bru.js`의 절대 경로를 지정한다.
외부 분석 API를 쓸 수 있는 백엔드와 장소가 포함된 공개 영상이 필요하다. 기본 영상은 `FyXT_7huLds`이며 기존 분석 결과를 재사용할 수 있다.

차단은 모델 호출 이전의 업무 정책이라 **기존 stub 모드 서버에서 검증할 수 있다**. 서버를 LLM 모드로 바꾸거나 새 서버를 띄울 필요가 없다.
조건을 복구한 대조 요청은 실제 실행 한 건·COMPLETED·NO_ACTION 또는 PROPOSE를 요구한다. 모델 판단의 품질이나 알림 내용은 검사하지 않는다.
LLM 서버를 지정하면 대조 요청에서 실제 모델 사용량이 발생할 수 있다. FCM 토큰은 등록하지 않아 실제 기기로 발송하지 않는다.

## 서버 설정과 일치시킬 값

기본값은 현재 백엔드의 `recall.max-event-age=30m`, `recall.member-cooldown=2h`를 기준으로 한다.
서버에서 변경했다면 다음 환경변수도 실제 값에 맞춰 지정한다. 이 변수는 서버 설정을 바꾸지 않는다.

```powershell
$env:RECALL_MAX_EVENT_AGE_MS = '1800000'
$env:RECALL_MEMBER_COOLDOWN_MS = '7200000'
```

쿨다운이 0으로 비활성화된 서버에서는 이 다섯 시나리오를 그대로 통과할 수 없다.
오래된 이벤트와 현재 이벤트의 시간 조건은 DB 서버의 시각을 기준으로도 확인한다.
쿨다운 만료 이후 재허용·정확한 시간 경계는 이번 범위에 포함하지 않는다.

## 결과·정리

- 초기 기준으로 88개 요청 파일을 실행한다. 분석이 진행 중이면 폴링 때문에 실제 호출 수는 늘어난다.
- `reports/policy.xml`에 헤더·본문을 제외한 결과를 남긴다. 보고서는 커밋하지 않는다.
- DB 조회는 회원의 동의·저장·트리거·전체 실행/알림 건수와 대상 이벤트 기록을 함께 확인한다. 직접 데이터를 수정하지 않는다.
- 시나리오 마지막에 개인 저장물과 세션을 정리한다. 회원과 공용 콘텐츠는 남을 수 있다.
- 일반 PR CI에는 연결하지 않는다. 저장·분석과 읽기 전용 DB 접근을 준비한 환경에서 수동 실행한다.
