### 꺼내기 에이전트는 어떻게 동작하는가

꺼내기 에이전트의 목표는 트리거된 장소를 반드시 추천하는 것이 아니다. **개인 저장물이 사용자를 지금 이 상황에 연결해 주었을 때, 무엇을 다시 보여줄 가치가 있는지 판단하는 것**이 목표다.

#### 1. 개인 저장물이 에이전트를 깨운다

사용자가 저장한 장소의 지오펜스에 진입하면 앱이 서버에 이벤트를 보낸다. 공용 풀이나 장소가 없는 저장물은 직접 이벤트를 발생시키지 않는다.

#### 2. 서버가 실행 가능 여부를 검사한다

서버는 트리거의 유효성, 중복 이벤트, 최근 알림 여부, 실행 예산을 확인한다. 통과한 이벤트만 에이전트에 전달한다.

#### 3. 에이전트가 출발점과 후보를 읽는다

에이전트는 트리거된 저장물의 요약과 특징을 읽고, 주변 개인 저장물과 장소가 없는 개인 저장물도 조회한다. 필요하면 공용 풀을 후보로 살펴본다.

#### 4. 무엇을 보여줄지 가설을 세운다

저장물의 의미, 현재 위치·시간, 다른 저장물과의 연결성을 바탕으로 가설을 만든다.

- 저장한 장소 한 곳을 방문하도록 제안한다.
    
- 어울리는 장소를 짧은 코스로 묶는다.
    
- 장소가 없는 저장 콘텐츠를 지금 다시 보여준다.
    
- 개인 저장물의 의도를 살리기 위해 공용 풀을 보충한다.
    
- 지금은 아무것도 제안하지 않는다.
    

#### 5. 가설에 필요한 정보만 확인한다

장소 방문 가설이라면 이용 가능 여부와 이동시간을 확인한다. 콘텐츠를 다시 보여주는 가설이라면 요약·적합한 상황·현재 시간과의 관련성을 확인한다. 임베딩 유사도와 사용자의 저장 경향은 후보를 찾는 단서로 쓸 예정이다.

#### 6. 결과에 따라 계획을 바꾼다

이동시간이 길면 코스를 축소할 수 있고, 트리거된 장소가 적합하지 않으면 다른 개인 저장물이나 콘텐츠로 가설을 바꿀 수 있다. 관련성 있는 공용 풀 후보가 없거나 제안할 이유가 약하면 장소를 억지로 채우지 않고 침묵한다.

#### 7. 바뀐 계획을 다시 검증한다

제안 대상이나 형태가 바뀌면 해당 가설에 필요한 정보를 다시 확인한다. 이 반복은 서버가 정한 실행시간과 도구 호출 예산 안에서 끝낸다.

#### 8. 최종 행동을 결정한다

- `PROPOSE`: 장소 방문, 짧은 코스 또는 저장 콘텐츠 다시 보기 중 지금 보여줄 이유가 있는 제안
    
- `NO_ACTION`: 충분한 근거가 없어 제안하지 않음
    

`PROPOSE`에는 제안 유형, 대상 저장물, 지금 제안하는 이유를 담는다. 서버는 제안 유형에 맞는 필수 정보와 중복 알림 등의 하드 제약을 마지막으로 검사한 뒤 전달한다. 이동거리는 장소를 제안할 때만 검사한다.

#### 9. 판단 과정을 기록한다

어떤 개인 저장물이 에이전트를 깨웠는지, 어떤 후보와 가설을 검토했는지, 도구 결과에 따라 계획이 어떻게 바뀌었는지, 최종적으로 제안하거나 침묵한 이유를 기록한다.

이 구조에서 에이전틱한 부분은 주변 장소를 채우는 행위가 아니다. **저장물을 계기로 여러 형태의 제안을 세우고, 필요한 증거를 확인하며, 상황에 맞지 않으면 계획을 바꾸거나 포기하는 과정**이다.

### 꺼내기 에이전트의 도구
- 현재 위치 주변의 검증된 개인 장소 조회
- 요약 기반 개인 저장물 의미 검색
- 주변 공용 풀 의미 검색
- 장소의 현재 이용 가능 여부 확인
- 이동시간·경로 확인
- 저장물 상세 조회
- 날씨 조회
