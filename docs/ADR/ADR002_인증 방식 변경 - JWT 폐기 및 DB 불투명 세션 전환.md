# 인증 방식 변경: JWT 폐기 및 DB 불투명 세션 전환

## 결정

자체 인증 방식을 `JWT Access Token + DB Refresh Token` 구조에서 `DB 기반 불투명 세션 토큰` 구조로 변경합니다.

카카오 액세스 토큰은 로그인 시 카카오 사용자를 확인하는 용도로만 사용합니다. 검증이 끝나면 서비스가 자체 세션 토큰을 발급하며, 이후 API 인증에는 이 토큰을 사용합니다.

## 기존 방식

기존에는 짧은 수명의 JWT Access Token과 `Device`에 해시로 저장한 Refresh Token을 함께 사용했습니다.

```text
카카오 로그인
→ JWT Access Token과 Refresh Token 발급
→ 일반 요청은 JWT 서명 검증
→ Access Token 만료 시 Refresh Token으로 재발급
→ 로그아웃 시 Device 삭제
```

이 방식은 일반 요청에서 인증을 위한 DB 조회를 제거하고, 장기 인증정보인 Refresh Token을 재발급 시점에만 사용한다는 장점이 있습니다.

## 재검토한 이유

현재 서비스는 서버 한 대와 사용자당 하나의 활성 기기를 전제로 하며, 인증 요청 규모도 크지 않습니다. 따라서 인증 DB 조회를 제거하거나 여러 서버에서 별도 세션 저장소 없이 인증해야 할 요구가 확인되지 않았습니다.

반면 기존 방식에는 다음 복잡성과 제약이 추가됩니다.

- Access Token과 Refresh Token의 발급·만료 정책을 각각 관리해야 함
- Refresh Token 재발급과 회전 과정에서 동시성 처리가 필요함
- 로그아웃으로 `Device`를 삭제해도 기존 Access Token은 만료 전까지 유효함
- JWT 서명 키와 검증 설정을 별도로 관리해야 함
- 로그인 상태는 `Device`에 저장하면서 일반 요청에서는 그 상태를 확인하지 않는 이중 구조가 생김

DB 불투명 세션은 요청마다 조회가 발생하지만, 현재 규모에서 병목이라고 판단할 근거는 없습니다. 오히려 `Device`를 로그인 상태의 단일 기준으로 사용할 수 있고 로그아웃, 회원 탈퇴 및 기기 교체를 다음 요청부터 즉시 반영할 수 있습니다.

## 대안 비교

| 항목 | JWT Access + DB Refresh | DB 불투명 세션 |
| --- | --- | --- |
| 클라이언트 토큰 | Access Token, Refresh Token | 세션 토큰 하나 |
| 일반 요청 인증 | JWT 서명 검증 | `Device` 조회 |
| 서버 저장 | Refresh Token 해시 | 세션 토큰 해시 |
| 로그아웃 반영 | Refresh는 즉시 폐기되지만 Access는 만료까지 유효 | 다음 요청부터 즉시 반영 |
| 재발급 처리 | 필요 | 필요 없음 |
| 서버 인증 상태 | JWT와 `Device`로 분산 | `Device`로 일원화 |
| 주요 비용 | 토큰 회전과 만료 관리 | 요청당 DB 조회 한 번 |

현재 요구사항에서는 DB 불투명 세션의 즉시 폐기와 상태 일원화가 더 중요하다고 판단했습니다.

## 변경 후 인증 흐름

```text
앱이 카카오 액세스 토큰 전달
→ 서버가 카카오 API로 사용자 검증
→ Member 조회 또는 생성
→ 암호학적으로 안전한 임의 세션 토큰 생성
→ 세션 토큰 해시와 만료 시각을 Device에 저장
→ 원문 세션 토큰을 앱에 한 번 반환

API 요청
→ Authorization: Bearer {sessionToken}
→ 서버가 토큰을 동일한 방식으로 해시
→ Device 조회 및 만료 여부 확인
→ 연결된 Member를 인증 주체로 사용

로그아웃
→ Device 삭제
→ 기존 세션 토큰 즉시 사용 불가
```

세션 토큰 원문은 DB에 저장하지 않습니다. 토큰 생성에 충분한 난수를 사용하고, 로그와 오류 응답에도 원문을 남기지 않습니다. 세션 만료기간은 구현 전에 별도로 확정합니다.

## 코드 변경 범위

- JWT 발급기와 서명·검증 설정 제거
- Access Token과 Refresh Token DTO 제거
- Refresh Token 재발급 API와 회전 로직 제거
- `Device.refreshTokenHash`를 세션 토큰 해시 필드로 변경
- `Device.refreshTokenExpiresAt`을 세션 만료 시각 필드로 변경
- 로그인 응답을 세션 토큰 하나로 변경
- Bearer 세션 토큰을 해시하여 `Device`를 조회하는 인증 처리 추가
- 로그아웃 시 인증된 `Device` 삭제
- 세션 토큰 해시 조회를 위한 UNIQUE 제약 적용

`Member` 생성의 `INSERT ... ON CONFLICT DO NOTHING`과 `Device` 생성·교체를 직렬화하기 위한 회원 행 잠금은 인증 방식과 별개의 동시성 처리이므로 유지합니다.

동일 계정으로 로그인이 동시에 처리되면 각 요청이 서로 다른 세션 토큰을 받을 수 있고 마지막에 저장된 토큰만 유효해질 수 있습니다. 데이터 중복 방지와 로그인 요청의 멱등성은 별개의 문제이므로 테스트 결과에 따라 별도로 처리합니다.
