# 컨텐츠 요약 임베딩 구현 결정

## 범위

저장 파이프라인의 분석 결과로 콘텐츠 요약 임베딩을 만들어 저장하기까지. 에이전트의 의미 검색 도구는 다음 단계에서 다룬다.

## 흐름

```
저장 파이프라인 결과 DTO
→ 요약이 있으면 임베딩 대상
→ 제목 + 요약 + 카테고리로 텍스트 구성
→ 임베딩 모델 호출 (트랜잭션 밖)
→ applyOutcome 트랜잭션에서 분석 결과와 벡터를 함께 저장
```

## 결정 사항

**모델**

- Vertex AI의 gemini-embedding-001을 사용한다.
- 다국어 지원과 한국어 품질, 기존 Vertex 인증을 그대로 쓸 수 있다는 점을 고려했다.

**차원**

- 768차원으로 줄여서 사용한다.
- pgvector의 HNSW·IVFFlat 인덱스는 기본 벡터 타입에서 2,000차원까지만 지원하므로, 이후 인덱스를 추가할 여지를 남긴다.
- 행 크기가 Postgres 페이지 안에 들어가고, 인덱스 없이 검색할 때의 거리 계산 비용도 줄어든다.
- 정확도 손실은 검색 실험에서 함께 확인한다.
- 차원을 바꾸려면 전체를 다시 임베딩해야 하지만 비용이 작아 부족하면 1536으로 올려 비교한다.

**정규화**

- 3,072가 아닌 차원은 모델이 정규화하지 않으므로 저장과 질의 모두 직접 정규화한다.

**task_type**

- 저장할 요약은 RETRIEVAL_DOCUMENT로 임베딩한다.
- 에이전트의 검색 질의는 RETRIEVAL_QUERY로 임베딩한다.

**임베딩 대상 텍스트**

- 제목, 요약, 카테고리를 이어 붙여 하나의 벡터로 만든다.
- 요약 불확실성, 날짜, YouTube Data API로 받은 원본 메타데이터는 포함하지 않는다.
- 검색 품질이 부족하면 측정 결과에 따라 질의 문장 개선이나 장소별 임베딩을 검토한다.

**임베딩 조건**

- 요약이 있으면 임베딩한다. SUCCESS, PARTIAL, 장소가 없는 SUCCESS를 모두 포함하고 FAILED만 제외한다.
- 콘텐츠 단위로 하나만 만들고 모든 저장자가 함께 사용한다.

**실패 처리**

- 임베딩 호출이 실패해도 분석 결과는 저장하고 벡터만 비워 둔다.

**저장**

- content에 벡터 컬럼과 임베딩을 만든 모델명을 기록하는 컬럼을 추가한다.
- pgvector 확장은 마이그레이션에서 켠다.
- 쓰기와 유사도 조회는 네이티브 쿼리로 처리한다.
