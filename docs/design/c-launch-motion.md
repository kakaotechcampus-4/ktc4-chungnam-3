## 1. 배경과 구현 방향

### 1.1 배경

- C안의 의미는 **"작고 흐린 것(잊힌 기억) → 크고 또렷한 것(다시 꺼낸 기억)"** 이다. 정지 아이콘만으로는 이 의미가 절반만 전달되고, 맨 앞 장이 떠올라 첫 카드가 되는 **움직임**이 의미의 나머지를 완성한다.
- 따라서 실행 모션은 장식이 아니라 아이콘과 첫 화면(근처 탭의 첫 카드)을 **같은 사물로 연결**하는 장치다.

### 1.2 제약(한계)

- **안드로이드 런처 아이콘은 움직일 수 없다.** 홈 화면 아이콘은 정지 이미지로만 제공한다.
- **Expo 네이티브 스플래시(`expo-splash-screen`)는 정지 이미지 + 배경색만 표시한다.** 키프레임 애니메이션을 넣을 수 없다.
- 새 네이티브 모듈은 넣지 않는다. Lottie 제작 파이프라인 등은 일정상 제외하고, 이미 앱에 있는 모듈로만 만든다.

### 1.3 해결책

- **2단 구조**로 구현한다.
    1. **네이티브 스플래시**: 보라 배경 + 정지 C안 글리프(앞장 + 점까지 있는 완성 상태)를 표시한다.
    2. **JS 오버레이 스플래시**: 네이티브 스플래시와 **픽셀 단위로 같은 화면**을 React Native 뷰로 그린 뒤, 네이티브 스플래시를 숨기고 그 위에서 모션을 재생한다.
- 모션은 **`react-native-reanimated`** 로 구현한다. 이미 개발 빌드에 들어 있어 모션만 바꿀 때는 다시 빌드하지 않는다.
- 단, 네이티브 스플래시(§5.1)는 네이티브 설정이다. 네이티브 → JS 전환 지점은 다시 만든 빌드(preview-mock APK 등)에서만 확인할 수 있다. Expo Go와 기존 개발 빌드는 Expo 기본 스플래시를 보여 준다.
- 기대효과: 네이티브 → JS 전환 지점에서 화면이 바뀌지 않으므로 사용자는 하나의 연속된 모션으로 인지한다.

### 2.2 이징

| 이름     | 값                                 | 쓰는 곳                                                                   |
| -------- | ---------------------------------- | ------------------------------------------------------------------------- |
| EASE     | `Easing.bezier(0.22, 0.7, 0.2, 1)` | 자리를 옮기는 구간: 링, 뒷장 가라앉기, 앞장 펼치기, §5.4 크로스페이드     |
| IN_OUT   | `Easing.inOut(Easing.ease)`        | 훑기(들림 · 내려옴), 훑기 멈춤, 뾱의 되튀기                               |
| 튀어나옴 | `Easing.out(Easing.quad)`          | 뾱의 첫 구간(1 → 1.24)                                                    |
| FADE     | `Easing.inOut(Easing.quad)`        | 투명도만 바꾸는 구간(점 · 배경 · 앞장 사라짐). `withTiming` 기본값과 같다 |

- 이징은 표의 행(구간)마다 따로 건다. 전체에 한 번 거는 것이 아니다.
- EASE는 초반에 빠르고 끝에서 길게 감속한다. "펼쳐져 자리에 내려앉는" 느낌이 이 곡선에서 나온다. 대칭 곡선으로 바꾸지 않는다.

### 2.3 아이콘 글리프 기하 (viewBox 100×100 기준)

모든 좌표는 글리프 박스 좌상단 기준이며, 실제 크기는 `글리프 크기 / 100` 을 곱해서 쓴다.

| 요소                   | x           | y   | 크기     | 라운드 | 채움               |
| ---------------------- | ----------- | --- | -------- | ------ | ------------------ |
| 뒷장 1(가장 작고 흐림) | 12          | 52  | 30×30    | 6.6    | 흰 장, 투명도 0.22 |
| 뒷장 2                 | 27          | 34  | 34×34    | 7.5    | 흰 장, 투명도 0.48 |
| 앞장                   | 46          | 14  | 40×40    | 8.8    | 흰 장, 투명도 1    |
| 점(원)                 | 중심 74, 26 | —   | 반지름 5 | —      | `#6B4E7A`          |

- 점의 중심은 앞장 기준 **가로 70%, 세로 30%** 위치다.
- 라운드 규칙: 모든 면은 **짧은 변의 22%**. 크기를 바꿔도 이 비율을 유지한다.
- 런처 아이콘 마스크 자체도 22% 라운드다(200px 기준 47px).

## 3. 앱 실행 모션 (핵심)

### 3.1 개요

- 시작 상태: 자두색 배경 중앙에 C안 글리프(완성 상태)가 있다. 네이티브 스플래시와 같다.
    - 글리프 박스는 **96dp**, 화면 정중앙: `glyphLeft = (screenW − 96) / 2`, `glyphTop = (screenH − 96) / 2`, 배율 `k = 96 / 100 = 0.96`.
- 두 단계로 나뉜다.
    1. **훑기(§3.3, 준비하는 동안 반복)**: 앱이 폰트 · 세션 · 도착 자리를 준비하는 동안 세 장을 뒤에서 앞으로(아래에서 위로) 차례로 들어 올린다. 1200ms 주기. 빠른 기기에서도 **최소 한 바퀴(1200ms)** 는 보인다.
    2. **끝맺음(§3.4, 1회)**: 준비되면 앞장이 "뾱" 튀어나오고, 뒷장 둘은 가라앉아 사라지고, 앞장이 도착 자리(S2)로 펼쳐진 뒤 배경이 걷히고 앞장이 실제 요소로 바뀐다. 1728ms(도착 대상이 없으면 1224ms).
- 총 길이: 준비가 1200ms 안에 끝나면 약 2.9초(1200 + 1728). 준비가 늦으면 훑기가 그만큼 더 돈다.
- 이야기 순서: **잊힌 장들이 차례로 떠오르려 한다(찾는 중) → 맨 앞 장이 "뾱" 하고 골라진다 → 흐린 장들은 가라앉는다 → 골라진 장이 펼쳐져 도착 화면의 대표 요소가 된다.**
- **도착 화면은 세션 유무에 따라 둘로 나뉜다.** 두 분기는 같은 타임라인을 쓰고 **도착 화면과 앞장의 도착 자리(S2)만 다르다.**

### 3.1.1 분기 규칙

| 분기             | 조건                                        | 도착 화면                    | 앞장의 도착 대상 (S2)                                                     | 의미                                            |
| ---------------- | ------------------------------------------- | ---------------------------- | ------------------------------------------------------------------------- | ----------------------------------------------- |
| **A. 세션 있음** | 기기에 저장된 세션(게스트 세션 포함)이 있다 | `C / 01 근처 · 다시 꺼낸 곳` | 근처 목록 **첫 번째 카드** `C/Card/Nearby`                                | 아이콘 속 앞장 = 지금 다시 꺼낸 기억            |
| **B. 세션 없음** | 저장된 세션이 없다 (첫 실행, 로그아웃 후)   | `C / 00a 시작 · 소개`        | 일러스트 `바랜 사진과 되살아난 사진`의 **맨 앞(가장 크고 또렷한) 썸네일** | 아이콘 속 계단 = 소개 일러스트의 겹친 사진 더미 |

- 분기 판정은 **로컬 저장소의 세션 토큰 존재 여부**로만 한다. 네트워크 요청(세션 유효성 검사 등)을 기다리지 않는다. 기다리면 그만큼 훑기가 길어진다.
- 저장된 세션이 서버에서 만료된 경우는 A로 재생한 뒤, 이후 API 응답에서 기존 만료 처리 흐름을 따른다. 실행 모션은 다시 재생하지 않는다.
- B의 근거: `C / 00a` 일러스트는 흐린 사진 3장 뒤에 크고 또렷한 사진 1장이 겹친 구성으로, C안 아이콘의 "흐린 뒷장 → 또렷한 앞장" 구조와 같다. 앞장이 맨 앞 썸네일 자리로 펼쳐지면 아이콘과 소개 일러스트가 같은 사물로 연결된다.

### 3.2 레이어 구조 (아래 → 위)

| 순서        | 레이어          | 내용                                                                                                                         |
| ----------- | --------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 1 (맨 아래) | **도착 화면**   | 분기 A: 근처 화면(위치 줄, 제목, 필터, 카드 목록, 하단 탭) / 분기 B: 시작 화면(일러스트, 문구, 시작하기 버튼). 실제 컴포넌트 |
| 2           | **자두색 배경** | 화면 전체 `#6B4E7A`                                                                                                          |
| 3           | **뒷장 1 · 2**  | 장마다 따로 움직인다(훑기에서 들리는 시각이 다르다)                                                                          |
| 4           | **링**          | 앞장 시작 자리(S0)의 테두리. 끝맺음의 "뾱"에서만 보인다                                                                      |
| 5 (맨 위)   | **앞장**        | 흰 사각형 1개 + 그 안의 점                                                                                                   |

- 앞장은 자두색 배경과 **별도 레이어**여야 한다. 배경이 사라진 뒤에도 앞장은 남아 도착 자리 위에 있어야 하기 때문이다.
- 모든 레이어는 `position: absolute` 로 오버레이(root) 기준 좌표를 쓴다.
- 기준 사각형
    - **앞장 시작 (S0)**: `left = glyphLeft + 46k`, `top = glyphTop + 14k`, `size = 40k = 38.4`, `radius = 8.8k ≈ 8.4`
    - **점**: 앞장 기준 가로 70%, 세로 30% 중심, 지름 `10k = 9.6`
    - **도착 자리 (S2)**: §3.5

### 3.3 1단계 훑기 (준비하는 동안 반복)

| 대상   | 시작 지연 (ms) | 들림 l: 0 → 1 | 내려옴 l: 1 → 0 | 쉼 (ms) | 주기 (ms) |
| ------ | -------------- | ------------- | --------------- | ------- | --------- |
| 뒷장 1 | 0              | 264ms, IN_OUT | 312ms, IN_OUT   | 624     | 1200      |
| 뒷장 2 | 160            | 264ms, IN_OUT | 312ms, IN_OUT   | 624     | 1200      |
| 앞장   | 320            | 264ms, IN_OUT | 312ms, IN_OUT   | 624     | 1200      |

들림 값 `l`(0 → 1)이 장에 주는 변화:

| 속성       | 값                      | 비고                                              |
| ---------- | ----------------------- | ------------------------------------------------- |
| opacity    | `base + (1 − base) · l` | base: 뒷장 1 0.22, 뒷장 2 0.48, 앞장 1(변화 없음) |
| translateY | `−3k · l`               | 위로 2.88dp                                       |
| scale      | `1 + (bump − 1) · l`    | bump: 뒷장 1.08, 앞장 1.06                        |

- 시작: 네이티브 스플래시를 숨기는 첫 프레임(§5.2).
- 1200ms 시점에는 세 장이 모두 내려와 있다(뒷장 1은 다음 주기를 막 시작, 나머지는 쉼). 최소 시간을 1200ms로 둔 이유다. 준비가 더 늦으면 어느 위치에서든 끝맺음 #1로 120ms 만에 제자리로 돌아온다.
- 애니메이션 줄이기에서는 훑지 않는다(§5.4).

### 3.4 2단계 끝맺음

`t`는 끝맺음 시작부터의 경과 시간이다. 시작 = max(준비된 시각, 훑기 시작 + 1200ms). 준비 = 폰트 · 세션을 읽고 도착 화면이 S2를 보고함(1000ms 안에 없으면 null, §6).

| #   | 대상        | 속성                                          | t (ms)                    | 값 변화                                                                 | 이징                  |
| --- | ----------- | --------------------------------------------- | ------------------------- | ----------------------------------------------------------------------- | --------------------- |
| 1   | 세 장       | 훑기 멈춤                                     | 0 → 120                   | l → 0                                                                   | IN_OUT                |
| 2   | 앞장        | scale (뾱)                                    | 0 → 144 → 252 → 360 → 468 | 1 → 1.24 → 0.92 → 1.05 → 1                                              | 튀어나옴, 이후 IN_OUT |
| 3   | 링          | 진행 r                                        | 0 → 396                   | 0 → 1. scale `0.9 + r`, opacity `0.7 · (1 − r)`                         | EASE                  |
| 4   | 뒷장 1 · 2  | 가라앉기 s                                    | 0 → 540                   | 0 → 1. opacity `× (1 − s)`, translateY `+14k · s`, scale `× (1 − 0.2s)` | EASE                  |
| 5   | 점          | opacity                                       | 540 → 756                 | 1 → 0                                                                   | FADE                  |
| 6   | 앞장        | left / top / width / height / radius / rotate | 612 → 1152                | S0 → S2                                                                 | EASE                  |
| 7   | 자두색 배경 | opacity                                       | 864 → 1224                | 1 → 0                                                                   | FADE                  |
| 8   | 앞장        | opacity                                       | 1512 → 1728               | 1 → 0                                                                   | FADE                  |
| 9   | 전체        | 종료                                          | 1728                      | 오버레이 언마운트                                                       | —                     |

- 도착 대상이 없으면(S2 = null) #6은 없고, #8은 864 → 1224(배경과 함께), #9는 1224다.
- 링: 두께 1.5dp, 색 `#FFFCFA`, 라운드는 S0와 같다. #3 동안만 보인다(r = 0일 때는 숨김).
- 수치는 `metrics.launch`(기하 · bump · 들림 · 가라앉기 · 링)와 `app/launch/LaunchSplash.tsx` 의 `SCAN` · `FINISH` · `POP`(시간)에 있다.

### 3.5 도착 자리 (S2)

- 분기별 도착 대상의 **실제 레이아웃**이다. 하드코딩하지 않고 대상 뷰의 `measureInWindow` 결과를 쓴다. 라운드는 대상 컴포넌트의 실제 `borderRadius`를 쓴다.

    | 분기         | 측정 대상                                            | Figma 기준값 (360×800 프레임)      | 형태 변화                              |
    | ------------ | ---------------------------------------------------- | ---------------------------------- | -------------------------------------- |
    | A. 세션 있음 | `C/Card/Nearby` (목록 `지금 가까운 곳` 첫 카드)      | `x 20, y 204, 320×223, radius 16`  | 38.4 정사각 → 가로로 넓은 카드         |
    | B. 세션 없음 | 일러스트 맨 앞 `C/Thumb` (Shorts 표식이 있는 썸네일) | `x 134, y 130, 120×213, radius 12` | 38.4 정사각 → 세로로 긴 사진, 0° → −4° |
    - Figma 기준값은 측정 결과 검수용이다. 실기기 측정값이 이 비율에서 크게 벗어나면 레이아웃 구현을 먼저 확인한다.
    - 프로토타입 아티팩트의 도착값(`252×128, radius 18`)과 시안 코드의 라운드 규칙(`min(짧은 변 × 0.22, 24)`)은 쓰지 않는다. 대상의 실제 라운드와 달라지면 #8 교체가 보인다.
    - B의 맨 앞 썸네일은 −4° 기울어 있다(`metrics.onboarding.intro`). 앞장은 #6 동안 0° → −4°로 함께 돌며 펼쳐진다. 회전 없이 덮으면 #8에서 흰 장과 사진의 모서리가 최대 약 7dp 어긋나 보인다. 회전 중심은 둘 다 사각형 중심이다.
    - 기울어진 뷰를 `measureInWindow`로 재면 회전된 꼭짓점이 나온다. B는 기울지 않은 일러스트 틀을 재고, 그릴 때와 같은 식(중심 − 크기/2)으로 맨 앞 썸네일 자리를 구한다. 기울기 값을 그대로 S2의 `rotate`로 넘긴다. 위 표의 B Figma 기준값은 x · y가 회전 뒤 외곽 상자 좌표이고 크기(120×213)는 회전 전 값이다. 중심(201.3, 212.1 + 상태바)으로 대조한다.

### 3.6 구간별 의도 (조정할 때 지켜야 할 것)

- **훑기(§3.3)**: "기억을 뒤적이는 중"을 보여 주며 로딩 표시를 겸한다. 최소 한 바퀴는 기기 속도와 상관없이 같은 모션이 보이게 한다. 빠른 기기에서 첫 장이 들리다 바로 끊기면 떨림처럼 보인다.
- **뾱(#2)과 링(#3)**: 맨 앞 장이 "지금 꺼낸 기억"으로 골라지는 순간이다.
- **뒷장이 아래로 가라앉음(#4)**: 잊힌 장들은 물러난다. 앞장이 펼쳐지기(#6) 전에 끝난다.
- **점이 사라짐(#5)**: 점은 아이콘에서만 쓰는 표식이다. 펼치기(#6)와 겹쳐 사라져야 첫 카드와 모양이 맞는다.
- **펼치기(#6)와 배경 걷힘(#7)이 겹침**: 앞장이 아직 펼쳐지는 중에 실제 화면이 비쳐 보인다. 이 겹침이 "아이콘 속 장이 곧 첫 카드"라는 연결을 만든다.
- **앞장이 S2에서 머무름(1152 → 1512)**: 배경이 다 걷힌(1224) 뒤에 앞장이 사라져 실제 요소로 바뀐다(#8).

### 3.7 도착 화면의 요구 사항

공통

- 도착 화면은 준비되는 즉시 **오버레이 아래에 렌더링되어** S2를 보고한다. 훑기가 도는 동안 그려지므로 측정이 끝맺음을 늦추지 않는다.
- 도착 화면 내부 요소는 배경 걷힘(#7)으로 함께 드러나므로 개별 모션을 넣지 않는다.
- 오버레이가 언마운트되기 전에는 아래 화면이 눌리지 않는다(오버레이가 화면 전체를 덮는다).

분기 A. 세션 있음 → `C / 01`

- 첫 카드 면 색은 `#FFFCFA`로 앞장과 같다. 따라서 #8은 **보이지 않는 교체**다. 앞장이 카드 면과 정확히 겹쳐야 한다.
- 첫 카드는 `지금 가까운 곳` 섹션의 `C/Card/Nearby`이다. 근처 카드가 없으면 §6을 따른다.

분기 B. 세션 없음 → `C / 00a`

- 도착 대상은 사진 썸네일이라 앞장(`#FFFCFA` 단색)과 면 색이 다르다. 따라서 #8은 **흰 장이 걷히며 사진이 드러나는 교체**가 된다. C안 문구 "사진에 색이 돌아와요"와 같은 의미다.
- #8은 216ms다. 예전 C안은 깜박임을 피하려고 360ms였으므로, 실기기에서 깜박임으로 보이면 B만 늘리는 것을 검토한다.
- 일러스트의 뒤쪽 흐린 썸네일 3장은 배경 걷힘(#7)으로만 드러난다. 뒷장(#4)을 이 썸네일로 옮기지 않는다. 뒷장 수(2)와 흐린 썸네일 수(3)가 달라 1:1 대응이 되지 않기 때문이다.
- 맨 앞 썸네일의 `source/Shorts` 표식(재생 아이콘)은 앞장이 덮고 있는 동안 가려지고 #8에서 드러난다.

## 5. 구현 가이드 (React Native + Expo)

### 5.1 네이티브 스플래시 설정

- `app.json`(또는 `app.config`)의 `expo-splash-screen` 설정
    - `backgroundColor`: `#6B4E7A`
    - `image`: **글리프만 있는 투명 배경 PNG** (뒷장 2장 + 앞장 + 점, §2.3). 보라 사각 배경을 포함하지 않는다.
    - `imageWidth`: **96** (§3.1 글리프 박스와 동일)
- 글리프 PNG는 `frontend/assets/images/splash-glyph.png`다. Figma에서 내보내지 않고 §2.3 수치로 직접 그린 1024×1024 투명 PNG다.
    - 이유: 이 문서의 수치가 Figma보다 우선이고, JS 오버레이(§3)도 같은 수치로 그리므로 두 화면이 정확히 겹친다.
    - PNG는 글리프만 잘라내지 않고 **viewBox 100×100 전체(투명 여백 포함)** 를 정사각으로 둔다. `expo-splash-screen`은 288dp 투명 캔버스 가운데에 이미지를 `imageWidth` dp로 contain 배치하므로, 여백을 잘라내면 크기와 중심이 §3.1 글리프 박스와 어긋난다.
    - §2.3 수치를 바꾸면 PNG를 다시 만든다.
- 앱 진입 시 `SplashScreen.preventAutoHideAsync()`를 먼저 호출한다.

### 5.1.1 앱 아이콘 · 알림 아이콘

- 아이콘도 §2.3 수치로 직접 그린 PNG다(스플래시 글리프와 같은 모양). Figma `아이콘 200` = 자두색 바탕 + `glyph`.

| 파일 (`frontend/assets/images/`)     | 설정 (`app.json`)                      | 내용                                                                                                               |
| ------------------------------------ | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `android-icon-foreground.png` (1024) | `android.adaptiveIcon.foregroundImage` | 투명 108dp 캔버스 가운데에 viewBox 100 = **66dp**(안전 영역 지름). 바탕은 `adaptiveIcon.backgroundColor` `#6B4E7A` |

- 알림 아이콘은 상태바에서 투명도로만 그려진다. 뒷장 1(0.22)은 24dp에서 거의 보이지 않지만 §2.3 투명도를 그대로 둔다. 앞장과 점 구멍으로 알아볼 수 있다.

### 5.2 네이티브 → JS 전환

1. 앱이 켜지면 `LaunchSplash`가 바로 뜬다. 폰트 · 세션을 기다리지 않는다(글자가 없어 폰트가 필요 없다).
2. 첫 레이아웃 뒤 다음 프레임(`requestAnimationFrame`)에 `SplashScreen.hide()`를 부르고 같은 콜백에서 훑기(§3.3)를 시작한다.
    - 네이티브 스플래시는 `SplashScreen.setOptions({ duration: 0 })`으로 페이드 없이 걷는다. 오버레이가 같은 화면이라 바로 바꿔도 티가 나지 않는다. Android 기본 400ms 페이드를 두면 정지된 글리프가 들리기 시작한 장 위에 겹쳐 보인다.
3. 폰트와 세션(로컬 저장소의 세션 토큰, §3.1.1)을 읽으면 분기에 맞는 도착 화면을 오버레이 아래에 렌더링한다. 오버레이는 같은 자리에 있어 다시 마운트되지 않는다.
4. 도착 화면이 S2를 보고하면(1000ms 안에 없으면 `null`, §6) 끝맺음(§3.4)을 시작한다. 훑기 시작 뒤 1200ms가 안 됐으면 그때까지 기다린다.
5. 끝맺음 #9 시각에 JS 타이머로 `onFinish`를 불러 오버레이를 언마운트한다.

- 도착 화면은 S2를 창 좌표(`measureInWindow`)로 보고한다. `LaunchSplash`는 자기 창 위치를 재서 빼고 오버레이 좌표로 쓴다. 오버레이가 창 원점에 있지 않은 기기(edge-to-edge가 아닌 경우)에서도 도착 위치가 맞는다.
- 끝맺음을 시작한 뒤에 들어온 보고는 무시한다.
- `LaunchSplash`는 분기를 모른다. 도착 화면이 측정한 **S2 사각형(left, top, width, height, radius, rotate)만 prop으로 받는다.** 두 분기가 같은 컴포넌트 · 같은 타임라인을 쓰고, 도착 화면 쪽은 "어느 뷰를 S2로 넘길지"만 책임진다.

```tsx
type Rect = {
    left: number;
    top: number;
    width: number;
    height: number;
    radius: number;
    rotate: number; // 도 단위. 기울지 않은 대상은 0
};

<LaunchSplash
    target={s2} // 준비 전: undefined(훑기) / A: 근처 첫 카드 / B: 맨 앞 썸네일 / 없음: null
    skipMotion={false} // 종료 상태 알림으로 08 이 열릴 때 true(§6)
    onFinish={() => setSplashDone(true)}
/>;
```

- 확인 항목: 실기기에서 네이티브 스플래시 글리프와 오버레이 글리프의 **위치·크기가 정확히 겹치는지** 화면 녹화로 확인한다. 상태바 · 내비게이션바 영역 처리(edge-to-edge 여부)에 따라 세로 중앙값이 달라질 수 있으므로, 어긋나면 `glyphTop` 계산에 해당 inset을 반영한다.

### 5.3 Reanimated 구현 패턴

- 훑기는 장마다 `withDelay(stagger, withRepeat(withSequence(들림, 내려옴, 쉼), -1))` 하나다. 끝맺음을 시작할 때 `cancelAnimation` 후 120ms에 0으로 돌린다(#1).
- 끝맺음은 표의 **한 행 = `withDelay(start, withTiming(to, { duration, easing }))` 하나**로 대응시킨다. 뾱(#2)처럼 같은 값에 여러 구간이 이어지면 `withSequence`로 잇는다.
- 앞장 펼치기(#6)는 진행값 하나(0 → 1)로 left / top / width / height / radius / rotate를 보간한다. 가로 · 세로 비율이 달라지므로 **`transform: scale`이 아니라 크기 · 라운드를 직접 바꾼다**(scale이면 라운드가 찌그러진다). 훑기 · 뾱의 크기 변화는 정사각 그대로라 scale을 쓴다.
- 뒷장은 장마다 따로 `Animated.View`다(들리는 시각이 다르다).
- 앱은 Reanimated 4다. 종료는 `runOnJS` 대신 JS 타이머로 부른다.
- 시안 코드(Reanimated 3)에서 앱에 맞춰 바꾼 점: 오버레이가 터치를 막음(시안은 `pointerEvents="none"`), 창 좌표 변환(시안은 `useWindowDimensions`), 실제 라운드 사용, B 기울기, 최소 훑기 한 바퀴, 색 토큰 · `metrics.launch`, 알림 진입 크로스페이드.

### 5.4 접근성

- 시스템 **애니메이션 줄이기**가 켜져 있으면(Reanimated `useReducedMotion()`) 훑기 없이 시작 상태로 멈춰 있다가, 준비되면 오버레이 전체를 **200ms 크로스페이드**로 걷는다(EASE).
- 종료 상태에서 누른 알림으로 실행해 도착 화면이 장소 상세(08)인 경우도 같은 크로스페이드를 쓴다(§6). 최소 훑기 시간을 기다리지 않는다.

- [ ] 네이티브 스플래시 → JS 오버레이 전환 시 글리프 위치·크기가 바뀌지 않는다.
