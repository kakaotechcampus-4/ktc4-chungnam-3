## 1. 배경과 구현 방향

### 1.1 배경

- C안의 의미는 **"작고 흐린 것(잊힌 기억) → 크고 또렷한 것(다시 꺼낸 기억)"** 이다. 정지 아이콘만으로는 이 의미가 절반만 전달되고, 맨 앞 장이 떠올라 첫 카드가 되는 **움직임**이 의미의 나머지를 완성한다.
- 따라서 실행 모션은 장식이 아니라 아이콘과 첫 화면(근처 탭의 첫 카드)을 **같은 사물로 연결**하는 장치다.

### 1.2 제약(한계)

- **안드로이드 런처 아이콘은 움직일 수 없다.** 홈 화면 아이콘은 정지 이미지로만 제공한다.
- **Expo 네이티브 스플래시(`expo-splash-screen`)는 정지 이미지 + 배경색만 표시한다.** 키프레임 애니메이션을 넣을 수 없다.
- 새 네이티브 모듈은 넣지 않는다. Lottie 제작 파이프라인 등은 일정상 제외하고, 이미 앱에 있는 모듈로만 만든다.

### 1.3 해결책

- **2단 구조**로 구현한다.
    1. **네이티브 스플래시**: 보라 배경 + 정지 C안 글리프(앞장 + 점까지 있는 완성 상태)를 표시한다.
    2. **JS 오버레이 스플래시**: 네이티브 스플래시와 **픽셀 단위로 같은 화면**을 React Native 뷰로 그린 뒤, 네이티브 스플래시를 숨기고 그 위에서 모션을 재생한다.
- 모션은 **`react-native-reanimated`** 로 구현한다. 이미 개발 빌드에 들어 있어 모션만 바꿀 때는 다시 빌드하지 않는다.
- 단, 네이티브 스플래시(§5.1)는 네이티브 설정이다. 네이티브 → JS 전환 지점은 다시 만든 빌드(preview-mock APK 등)에서만 확인할 수 있다. Expo Go와 기존 개발 빌드는 Expo 기본 스플래시를 보여 준다.
- 기대효과: 네이티브 → JS 전환 지점에서 화면이 바뀌지 않으므로 사용자는 하나의 연속된 모션으로 인지한다.

## 2. 공통 값

### 2.1 색

| 용도              | 값        | Figma 토큰                  |
| ----------------- | --------- | --------------------------- |
| 스플래시 배경, 점 | `#6B4E7A` | `C · Primitive / dusk/500`  |
| 카드 면(흰 장)    | `#FFFCFA` | `C · Primitive / linen/0`   |
| 앱 화면 배경      | `#F6F1EE` | `C · Primitive / linen/100` |
| 구분선            | `#ECE4E0` | `C · Primitive / linen/200` |
| 본문 진한 글자    | `#2A2126` | `C · Primitive / mauve/900` |
| 보조 글자         | `#6A5D61` | `C · Primitive / mauve/500` |

- 앱에 토큰 상수가 있으면 위 hex 대신 해당 토큰을 쓴다.

### 2.2 이징

- 모든 구간에 **`cubic-bezier(0.22, 0.7, 0.2, 1)`** 을 쓴다.
    - Reanimated: `Easing.bezier(0.22, 0.7, 0.2, 1)`
- 원본 CSS는 이징을 **키프레임 구간마다 따로** 적용한다. 즉 0→1000ms 전체에 한 번 거는 것이 아니라, 아래 표의 각 행(구간)마다 시작부터 끝까지 이 곡선을 한 번씩 적용한다.
- 성격: 초반에 빠르게 움직이고 끝에서 길게 감속한다. "떠올라서 자리에 내려앉는" 느낌이 이 곡선에서 나온다. `Easing.inOut` 같은 대칭 곡선으로 바꾸면 안 된다.

### 2.3 아이콘 글리프 기하 (viewBox 100×100 기준)

모든 좌표는 글리프 박스 좌상단 기준이며, 실제 크기는 `글리프 크기 / 100` 을 곱해서 쓴다.

| 요소                   | x           | y   | 크기     | 라운드 | 채움               |
| ---------------------- | ----------- | --- | -------- | ------ | ------------------ |
| 뒷장 1(가장 작고 흐림) | 12          | 52  | 30×30    | 6.6    | 흰 장, 투명도 0.22 |
| 뒷장 2                 | 27          | 34  | 34×34    | 7.5    | 흰 장, 투명도 0.48 |
| 앞장                   | 46          | 14  | 40×40    | 8.8    | 흰 장, 투명도 1    |
| 점(원)                 | 중심 74, 26 | —   | 반지름 5 | —      | `#6B4E7A`          |

- 점의 중심은 앞장 기준 **가로 70%, 세로 30%** 위치다.
- 라운드 규칙: 모든 면은 **짧은 변의 22%**. 크기를 바꿔도 이 비율을 유지한다.
- 런처 아이콘 마스크 자체도 22% 라운드다(200px 기준 47px).

## 3. 앱 실행 모션 (핵심)

### 3.1 개요

- **총 길이 3000ms, 1회 재생.** (프로토타입은 5400ms 간격으로 반복하지만 이는 시연용이며 앱에서는 반복하지 않는다.)
- 시작 상태: 보라 배경 중앙에 C안 글리프(완성 상태)가 있다. 네이티브 스플래시와 동일하다.
- 이야기 순서: **흐린 두 장이 뒤로 빠진다 → 맨 앞 장이 한 칸 더 올라선다 → 앞장이 커져 도착 화면의 대표 요소가 된다 → 보라 배경이 걷히고 실제 화면이 드러난다.**
- **도착 화면은 세션 유무에 따라 둘로 나뉜다.** 타임라인(§3.4)은 두 분기가 완전히 같고, **도착 화면과 앞장의 도착 사각형(S2)만 다르다.**

### 3.1.1 분기 규칙

| 분기             | 조건                                        | 도착 화면                    | 앞장의 도착 대상 (S2)                                                     | 의미                                            |
| ---------------- | ------------------------------------------- | ---------------------------- | ------------------------------------------------------------------------- | ----------------------------------------------- |
| **A. 세션 있음** | 기기에 저장된 세션(게스트 세션 포함)이 있다 | `C / 01 근처 · 다시 꺼낸 곳` | 근처 목록 **첫 번째 카드** `C/Card/Nearby`                                | 아이콘 속 앞장 = 지금 다시 꺼낸 기억            |
| **B. 세션 없음** | 저장된 세션이 없다 (첫 실행, 로그아웃 후)   | `C / 00a 시작 · 소개`        | 일러스트 `바랜 사진과 되살아난 사진`의 **맨 앞(가장 크고 또렷한) 썸네일** | 아이콘 속 계단 = 소개 일러스트의 겹친 사진 더미 |

- 분기 판정은 **로컬 저장소의 세션 토큰 존재 여부**로만 한다. 네트워크 요청(세션 유효성 검사 등)을 기다리지 않는다. 기다리면 0ms 정지 구간이 늘어나 모션이 지연된다.
- 저장된 세션이 서버에서 만료된 경우는 A로 재생한 뒤, 이후 API 응답에서 기존 만료 처리 흐름을 따른다. 실행 모션은 다시 재생하지 않는다.
- B의 근거: `C / 00a` 일러스트는 흐린 사진 3장 뒤에 크고 또렷한 사진 1장이 겹친 구성으로, C안 아이콘의 "흐린 뒷장 → 또렷한 앞장" 구조와 같다. 앞장이 맨 앞 썸네일 자리에 내려앉으면 아이콘과 소개 일러스트가 같은 사물로 연결된다.

### 3.2 레이어 구조 (아래 → 위)

| 순서        | 레이어        | 내용                                                                                                                         |
| ----------- | ------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 1 (맨 아래) | **도착 화면** | 분기 A: 근처 화면(위치 줄, 제목, 필터, 카드 목록, 하단 탭) / 분기 B: 시작 화면(일러스트, 문구, 시작하기 버튼). 실제 컴포넌트 |
| 2           | **보라 배경** | 화면 전체 `#6B4E7A`                                                                                                          |
| 3           | **뒷장 묶음** | 뒷장 1, 뒷장 2 (글리프 박스 안)                                                                                              |
| 4 (맨 위)   | **앞장**      | 흰 사각형 1개 + 그 안의 점                                                                                                   |

- 앞장은 보라 배경과 **별도 레이어**여야 한다. 보라 배경이 사라진 뒤에도 앞장은 남아 첫 카드 위로 이동해야 하기 때문이다.
- 앞장은 `position: absolute` 로 화면(root) 기준 좌표를 쓴다.

### 3.3 기준 좌표

프로토타입은 화면 288×608(px) 기준으로 작성되어 있다. 앱에서는 아래 **상대 규칙**으로 계산한다.

- **글리프 박스**: 크기 **96dp**, 화면 정중앙에 배치한다.
    - `glyphLeft = (screenW - 96) / 2`, `glyphTop = (screenH - 96) / 2`
    - 배율 `k = 96 / 100 = 0.96`
- **앞장 시작 사각형 (S0)**: 글리프 박스 안 앞장 위치
    - `left = glyphLeft + 46k`, `top = glyphTop + 14k`, `size = 40k = 38.4`, `radius = 8.8k ≈ 8.4`
- **앞장 중간 사각형 (S1, "한 칸 더 올라섬")**: S0에서 크기는 그대로, 위치만 이동
    - `left = S0.left + 5.8`, `top = S0.top − 14.4`
- **앞장 도착 사각형 (S2)**: 분기별 도착 대상의 **실제 레이아웃**. 하드코딩하지 않고 대상 뷰의 `measureInWindow` 결과를 쓴다. 라운드는 대상 컴포넌트의 실제 `borderRadius`를 쓴다.

    | 분기         | 측정 대상                                            | Figma 기준값 (360×800 프레임)      | 형태 변화                              |
    | ------------ | ---------------------------------------------------- | ---------------------------------- | -------------------------------------- |
    | A. 세션 있음 | `C/Card/Nearby` (목록 `지금 가까운 곳` 첫 카드)      | `x 20, y 204, 320×223, radius 16`  | 38.4 정사각 → 가로로 넓은 카드         |
    | B. 세션 없음 | 일러스트 맨 앞 `C/Thumb` (Shorts 표식이 있는 썸네일) | `x 134, y 130, 120×213, radius 12` | 38.4 정사각 → 세로로 긴 사진, 0° → −4° |
    - Figma 기준값은 측정 결과 검수용이다. 실기기 측정값이 이 비율에서 크게 벗어나면 레이아웃 구현을 먼저 확인한다.
    - 프로토타입 아티팩트의 도착값(`252×128, radius 18`)은 초기 시안 값이므로 쓰지 않는다.
    - B의 맨 앞 썸네일은 −4° 기울어 있다(`metrics.onboarding.intro`). 앞장은 #7 동안 0° → −4°로 함께 돌며 내려앉는다. 회전 없이 덮으면 #11에서 흰 장과 사진의 모서리가 최대 약 7dp 어긋나 보인다. 회전 중심은 둘 다 사각형 중심이다.
    - 기울어진 뷰를 `measureInWindow`로 재면 회전된 꼭짓점이 나온다. B는 기울지 않은 일러스트 틀을 재고, 그릴 때와 같은 식(중심 − 크기/2)으로 맨 앞 썸네일 자리를 구한다. 기울기 값을 그대로 S2의 `rotate`로 넘긴다. 위 표의 B Figma 기준값은 x · y가 회전 뒤 외곽 상자 좌표이고 크기(120×213)는 회전 전 값이다. 중심(201.3, 212.1 + 상태바)으로 대조한다.

- **점**: 앞장 기준 가로 70%, 세로 30% 중심, 지름 `10k = 9.6`.

### 3.4 타임라인

`t`는 오버레이에서 모션을 시작한 시점부터의 경과 시간이다. 표에 없는 구간에서는 값이 유지된다.

| 6   | 앞장      | 점 opacity                                    | 660 → 1140     | 1 → 0                 | 22–38% |
| 7   | 앞장      | left / top / width / height / radius / rotate | 960 → 1920     | S1 → S2               | 32–64% |
| 8   | 보라 배경 | opacity                                       | 1500 → 2100    | 1 → 0                 | 50–70% |

| 11  | 앞장      | opacity                                       | 2520 → 2880    | 1 → 0                 | 84–96% |
| 12  | 전체      | 종료                                          | 3000           | 오버레이 언마운트     | 100%   |

각 행에 §2.2 이징을 따로 적용한다.

### 3.5 구간별 의도 (조정할 때 지켜야 할 것)

- **0–450ms 정지**: 네이티브 스플래시에서 JS 오버레이로 넘어온 직후 사용자가 아이콘을 한 번 인지하는 시간이다. 줄이면 아이콘을 보기 전에 움직임이 시작된다.
- **뒷장이 왼쪽 아래로 빠짐(#2, #3)**: "잊힌 것은 뒤로 물러난다"는 표현이다. 방향은 앞장의 이동 방향(오른쪽 위)과 **반대**여야 한다.
- **앞장이 먼저 살짝 오른쪽 위로(#5)**: 계단을 "한 칸 더" 오르는 동작이다. 이 단계 없이 바로 커지면 C안의 계단 의미가 사라진다.
- **점이 사라짐(#6)**: 점은 아이콘에서만 쓰는 표식이다. 카드가 되기 전에 사라져야 첫 카드와 모양이 맞는다.
- **앞장 확대(#7)와 배경 걷힘(#8)이 겹침**: 1500ms부터 배경이 걷히기 시작하므로, 앞장이 아직 커지는 중에 실제 화면이 비쳐 보인다. 이 겹침이 "아이콘 속 장이 곧 첫 카드"라는 연결을 만든다.
- **앞장이 S2에서 600ms 머무름(#10)**: 이 동안 도착 화면이 완전히 드러나고(#9 종료 2460ms), 그 뒤에 앞장이 사라져 실제 요소로 교체된다(#11).

### 3.6 도착 화면의 요구 사항

공통

- 모션 시작 전에 도착 화면이 **오버레이 아래에 이미 렌더링되어 있어야** 한다. 그래야 S2를 측정할 수 있다.
- 도착 화면 내부 요소는 #9로 함께 드러나므로 개별 모션을 넣지 않는다.

분기 A. 세션 있음 → `C / 01`

- 첫 카드 면 색은 `#FFFCFA`로 앞장과 같다. 따라서 #11은 **보이지 않는 교체**다. 앞장이 카드 면과 정확히 겹쳐야 한다.
- 첫 카드는 `지금 가까운 곳` 섹션의 `C/Card/Nearby`이다. 근처 카드가 없으면 §6을 따른다.

분기 B. 세션 없음 → `C / 00a`

- 도착 대상은 사진 썸네일이라 앞장(`#FFFCFA` 단색)과 면 색이 다르다. 따라서 #11은 **흰 장이 걷히며 사진이 드러나는 교체**가 된다. 이것은 의도된 표현이다. C안 문구 "사진에 색이 돌아와요"와 같은 의미로, 흰 장이 사라지면서 또렷한 사진이 나타난다.
- 이 때문에 B에서는 #11의 길이(360ms)를 줄이지 않는다. 너무 빠르면 깜박임으로 보인다.
- 일러스트의 뒤쪽 흐린 썸네일 3장은 #9(도착 화면 전체 페이드인)로만 드러난다. 뒷장 묶음(#2, #3)을 이 썸네일로 이동시키지 않는다. 뒷장 수(2)와 흐린 썸네일 수(3)가 달라 1:1 대응이 되지 않기 때문이다.
- 맨 앞 썸네일의 `source/Shorts` 표식(재생 아이콘)도 #9로 함께 드러난다. 앞장이 덮고 있는 동안(#10)은 가려지고 #11에서 드러난다.
- 시작하기 버튼은 #9 종료(2460ms) 전에는 눌러도 반응하지 않게 한다. 오버레이가 언마운트되는 3000ms 이후부터 입력을 받는다.

## 4. 아이콘 생성 모션 (보조)

- 아이콘이 "만들어지는" 과정을 보여주는 루프 모션이다. 실행 모션(§3)과 별개다.
- **적용 위치는 아직 정해지지 않았다.** 후보: 저장 분석 중(`C / 03`) 로딩 표시. 적용이 정해지면 이 값을 쓴다.
- `C / 00a 시작 · 소개`에는 쓰지 않는다. 실행 모션 분기 B(§3.1.1)가 이미 같은 계단 표현으로 이 화면에 도착하기 때문이다.
- Figma C안 보드의 `아이콘 모션 키프레임` 4장이 아래 표의 대표 상태다.

### 4.1 사양

- **2800ms 루프**, 이징은 §2.2와 같다.
- 뒷장 1, 뒷장 2는 **정지**(투명도 0.22 / 0.48 고정)다.
- 앞장은 **외곽선(stroke) 2.5(viewBox 단위)** 를 항상 가지며, 채움(fill) 투명도가 따로 움직인다.

| #   | 대상      | 속성           | 시작 → 끝 (ms) | 값 변화                  | 원본 %  |
| --- | --------- | -------------- | -------------- | ------------------------ | ------- |
| 1   | 앞장 묶음 | 위치           | 0 → 224        | (−17, +18)% 위치 유지    | 0–8%    |
| 2   | 앞장 묶음 | opacity        | 0 → 224        | 0 → 0.4                  | 0–8%    |
| 3   | 앞장 묶음 | 대기           | 224 → 504      | (−17, +18)%, opacity 0.4 | 8–18%   |
| 4   | 앞장 묶음 | translateX / Y | 504 → 1540     | (−17%, +18%) → (0, 0)    | 18–55%  |
| 5   | 앞장 묶음 | opacity        | 504 → 1540     | 0.4 → 1                  | 18–55%  |
| 6   | 앞장 채움 | fill opacity   | 616 → 1540     | 0 → 1                    | 22–55%  |
| 7   | 점        | opacity        | 1176 → 1736    | 0 → 1                    | 42–62%  |
| 8   | 앞장 묶음 | 대기           | 1540 → 2408    | 완성 상태 유지           | 55–86%  |

- 루프가 다시 시작될 때 #9에서 0이 된 상태가 #1의 0으로 이어지므로 끊김이 없다.

## 5. 구현 가이드 (React Native + Expo)

### 5.1 네이티브 스플래시 설정

- `app.json`(또는 `app.config`)의 `expo-splash-screen` 설정
    - `backgroundColor`: `#6B4E7A`
    - `image`: **글리프만 있는 투명 배경 PNG** (뒷장 2장 + 앞장 + 점, §2.3). 보라 사각 배경을 포함하지 않는다.
    - `imageWidth`: **96** (§3.3 글리프 박스와 동일)
- 글리프 PNG는 `frontend/assets/images/splash-glyph.png`다. Figma에서 내보내지 않고 §2.3 수치로 직접 그린 1024×1024 투명 PNG다.
    - 이유: 이 문서의 수치가 Figma보다 우선이고, JS 오버레이(§3)도 같은 수치로 그리므로 두 화면이 정확히 겹친다.
    - PNG는 글리프만 잘라내지 않고 **viewBox 100×100 전체(투명 여백 포함)** 를 정사각으로 둔다. `expo-splash-screen`은 288dp 투명 캔버스 가운데에 이미지를 `imageWidth` dp로 contain 배치하므로, 여백을 잘라내면 크기와 중심이 §3.3 글리프 박스와 어긋난다.
    - §2.3 수치를 바꾸면 PNG를 다시 만든다.
- 앱 진입 시 `SplashScreen.preventAutoHideAsync()`를 먼저 호출한다.

### 5.1.1 앱 아이콘 · 알림 아이콘

- 아이콘도 §2.3 수치로 직접 그린 PNG다(스플래시 글리프와 같은 모양). Figma `아이콘 200` = 자두색 바탕 + `glyph`.

| 파일 (`frontend/assets/images/`)     | 설정 (`app.json`)                      | 내용                                                                                                               |
| ------------------------------------ | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `android-icon-foreground.png` (1024) | `android.adaptiveIcon.foregroundImage` | 투명 108dp 캔버스 가운데에 viewBox 100 = **66dp**(안전 영역 지름). 바탕은 `adaptiveIcon.backgroundColor` `#6B4E7A` |
| `android-icon-monochrome.png` (1024) | `android.adaptiveIcon.monochromeImage` | 테마 아이콘(Android 13+). 같은 배치, 흰색 단색. 뒷장 투명도 유지, 점은 구멍                                        |
| `icon.png` (1024)                    | `icon`                                 | 자두색 정사각 전체(마스크는 런처 · 스토어가 씌움). 글리프는 적응형과 같은 비율(보이는 72dp 중 66dp)                |

- 안전 영역: 글리프의 가장 먼 점(앞장 오른쪽 위 라운드)이 중심에서 viewBox 47.3 = 31.25dp다. 안전 원(반지름 33dp) 안이라 원 · 둥근 사각 · 스쿼클 어떤 마스크에서도 잘리지 않는다.
- 알림 아이콘은 상태바에서 투명도로만 그려진다. 뒷장 1(0.22)은 24dp에서 거의 보이지 않지만 §2.3 투명도를 그대로 둔다. 앞장과 점 구멍으로 알아볼 수 있다.

### 5.2 네이티브 → JS 전환

0. 로컬 저장소에서 세션 토큰을 읽어 **분기(A/B)를 결정**한다(§3.1.1). 네이티브 스플래시가 떠 있는 동안 처리한다.
1. 분기에 맞는 도착 화면(`C / 01` 또는 `C / 00a`)을 오버레이 아래에 렌더링한다.
2. 오버레이 스플래시(`LaunchSplash`)가 §3 시작 상태로 첫 렌더를 마친다(`onLayout`).
3. 분기별 S2 대상(근처 첫 카드 / 맨 앞 썸네일)의 측정이 끝난다.
4. 2, 3이 모두 만족되면 `SplashScreen.hideAsync()`를 호출하고, 같은 프레임에 타임라인을 시작한다.

- 2, 3보다 `hideAsync()`가 먼저 실행되면 깜박임이 생긴다.
- 실제 구현은 2, 3을 만족한 다음 프레임(`requestAnimationFrame`)에 `SplashScreen.hide()`를 부르고 같은 콜백에서 타임라인을 시작한다. 시작 상태가 화면에 그려진 뒤에 숨기기 위해서다.
- Android의 네이티브 스플래시는 숨길 때 기본으로 400ms 페이드아웃한다. §3 모션에서는 이 페이드를 그대로 둔다. 0–450ms 정지 구간 안에서 끝나고, 두 글리프가 1~2px 어긋나도 가려 준다. §5.4 크로스페이드에서는 오버레이가 페이드를 맡으므로 `SplashScreen.setOptions({ duration: 0 })`으로 네이티브 스플래시를 바로 걷는다.
- 도착 화면은 S2를 창 좌표(`measureInWindow`)로 보고한다. `LaunchSplash`는 자기 창 위치를 재서 빼고 오버레이 좌표로 쓴다. 오버레이가 창 원점에 있지 않은 기기(edge-to-edge가 아닌 경우)에서도 도착 위치가 맞는다.
- 도착 화면이 S2를 보고하지 않으면 최대 1000ms 뒤 `target = null`로 시작한다(§6). 시작한 뒤에 들어온 보고는 무시한다.
- `LaunchSplash`는 분기를 모른다. 도착 화면이 측정한 **S2 사각형(left, top, width, height, radius, rotate)만 prop으로 받는다.** 이렇게 하면 두 분기가 같은 컴포넌트·같은 타임라인을 쓰고, 도착 화면 쪽은 "어느 뷰를 S2로 넘길지"만 책임진다.

```tsx
type Rect = {
    left: number;
    top: number;
    width: number;
    height: number;
    radius: number;
    rotate: number; // 도 단위. 기울지 않은 대상은 0
};

<LaunchSplash
    target={s2} // 분기 A: 근처 첫 카드 측정값 / 분기 B: 맨 앞 썸네일 측정값 / 없음: null
    onFinish={() => setSplashDone(true)}
/>;
```

- 확인 항목: 실기기에서 네이티브 스플래시 글리프와 오버레이 글리프의 **위치·크기가 정확히 겹치는지** 화면 녹화로 확인한다. 상태바·내비게이션바 영역 처리(edge-to-edge 여부)에 따라 세로 중앙값이 달라질 수 있으므로, 어긋나면 `glyphTop` 계산에 해당 inset을 반영한다.

### 5.3 Reanimated 구현 패턴

- 타임라인 표의 **한 행 = `withDelay(start, withTiming(end, { duration, easing }))` 하나**로 1:1 대응시킨다. 이렇게 하면 표와 코드를 줄 단위로 대조할 수 있다.
- 같은 속성에 여러 구간이 있으면 `withSequence`로 잇는다.
- 앞장의 크기 변화(#7)는 가로·세로 비율이 달라지므로(38.4 정사각 → 가로로 넓은 카드 · 세로로 긴 사진) **`transform: scale`이 아니라 `width` / `height` / `left` / `top` / `borderRadius`를 직접 애니메이션**한다. scale을 쓰면 라운드가 찌그러진다. 애니메이션 대상이 뷰 1개라 성능 문제는 없다.

```tsx
import {
    Easing,
    withDelay,
    withTiming,
    withSequence,
} from "react-native-reanimated";

const EASE = Easing.bezier(0.22, 0.7, 0.2, 1);
const seg = (start: number, end: number, to: number) =>
    withDelay(start, withTiming(to, { duration: end - start, easing: EASE }));

// 예: 뒷장 묶음 (#2, #3)
pileOpacity.value = seg(450, 1140, 0);
pileX.value = seg(450, 1140, -10);
pileY.value = seg(450, 1140, 16);

// 예: 앞장 위치 (#5 → #7) — 같은 값에 두 구간이므로 sequence
frontLeft.value = withSequence(
    seg(450, 960, S1.left), // 450ms 대기 후 510ms
    withTiming(S2.left, { duration: 960, easing: EASE }), // 960 → 1920
);
// width/height/radius는 #7만 있으므로 seg(960, 1920, S2.*)

// 예: 앞장 사라짐 (#11)
frontOpacity.value = seg(2520, 2880, 0);
```

- 타임라인을 시작한 시각부터 3000ms 뒤 JS 타이머로 `onFinish`를 불러 오버레이를 언마운트한다. 마지막 애니메이션(#11) 콜백이 아니라 **3000ms 기준**으로 종료한다.
- 뒷장 묶음은 `react-native-svg`로 그려도 되고 `View` 2개로 그려도 된다. 움직이는 단위가 묶음 전체이므로 하나의 `Animated.View`로 감싼다.

### 5.4 접근성

- 시스템 **애니메이션 줄이기**가 켜져 있으면(Reanimated `useReducedMotion()`) §3 모션을 생략하고, 보라 배경 → 실제 화면을 **200ms 크로스페이드**로만 전환한다.
- 종료 상태에서 누른 알림으로 실행해 도착 화면이 장소 상세(08)인 경우도 같은 크로스페이드를 쓴다(§6).

## 7. 완료 기준 (구현 검수 체크리스트)

- [ ] 네이티브 스플래시 → JS 오버레이 전환 시 글리프 위치·크기가 바뀌지 않는다.
- [ ] 전체 길이가 3000ms이고 반복하지 않는다.
- [ ] 모든 구간에 `Easing.bezier(0.22, 0.7, 0.2, 1)`이 구간별로 적용된다.
- [ ] 뒷장은 왼쪽 아래로, 앞장은 오른쪽 위로 움직인다.
- [ ] 앞장이 커지기 전에 점이 사라진다.
- [ ] 세션이 있으면 `C / 01`, 없으면 `C / 00a`로 도착하며, 판정에 네트워크를 기다리지 않는다.
- [ ] 두 분기가 같은 `LaunchSplash` 컴포넌트와 같은 타임라인을 쓰고, `target`만 다르다.
- [ ] 분기 A: 앞장 도착 위치가 근처 첫 카드와 dp 단위로 일치하고, #11 교체 순간이 보이지 않는다.
- [ ] 분기 B: 앞장 도착 위치가 일러스트 맨 앞 썸네일과 일치하고, #11에서 흰 장이 걷히며 사진이 드러난다.
- [ ] 분기 B: 3000ms 전에는 시작하기 버튼이 반응하지 않는다.
- [ ] 화면 크기가 다른 기기 2종 이상에서 도착 위치가 맞는다(하드코딩 없음).
- [ ] 애니메이션 줄이기가 켜진 기기에서 200ms 크로스페이드로 대체된다.
- [ ] 화면 녹화를 프로토타입 아티팩트와 나란히 놓고 비교했을 때 순서·속도가 같다.
