# YouTube 콘텐츠 분석 경로 변경: Elice ML API 제약과 Vertex AI 대안 검증

## 1. 문제 정의

우리 서비스는 사용자가 공유한 YouTube 콘텐츠에서 제목·설명 등의 메타데이터와 영상 내부의 장소 정보를 추출해야 한다.

초기에는 다음 흐름으로 구현할 예정이었다.

```text
YouTube URL 입력
→ YouTube Data API로 메타데이터 조회
→ Gemini로 영상 내용 분석
→ 요약 및 장소 후보 추출
→ 장소검색 API로 실제 장소 검증
```

그러나 교육 과정에서 제공된 Elice 환경만으로는 이 흐름을 구현할 수 없었다.

- Elice ML API에서는 Gemini 모델을 제공하지만, 공개 YouTube URL을 영상 입력으로 전달하는 방식을 지원하지 않음
    
- YouTube Data API도 별도로 제공되지 않으므로 직접 Google Cloud 환경을 구성해야 함
    

이로 인해 영상의 음성이나 화면에만 장소가 등장하는 콘텐츠를 분석할 수 없어 콘텐츠 저장 흐름이 막히는 문제가 발생했다.

## 2. 초기 기획과 달라진 점

초기에는 Elice에서 Gemini 모델을 제공한다는 점만 확인하고, Gemini의 영상 입력 기능도 동일하게 사용할 수 있을 것으로 예상했다.

하지만 Gemini 모델이 가진 기능과 Elice ML API가 외부에 노출한 기능은 동일하지 않았다. Elice ML API에서 다음 요청을 직접 시험했지만 모두 실패했다.

|시도|결과|
|---|---|
|`/v1/chat/completions`에 `video` 전달|400 `Invalid content part type: video`|
|`/v1/chat/completions`에 `file` 전달|400 `Invalid content part type: file`|
|`/v1/interactions` 호출|404|
|`/v1beta/interactions` 호출|404|

따라서 문제의 원인은 Gemini 모델의 영상 이해 능력이 아니라, Elice ML API의 OpenAI 호환 인터페이스에서 Gemini의 YouTube URL 입력 방식을 제공하지 않는 것이었다.

## 3. 대안 검토

### 3.1 YouTube 메타데이터만 분석

YouTube Data API를 사용하면 제목·설명·태그·채널·게시일·썸네일 등의 메타데이터를 조회할 수 있다.

하지만 장소가 영상의 음성이나 화면 자막에만 등장하는 경우에는 정보를 추출할 수 없다. 따라서 메타데이터만으로는 핵심 기능을 안정적으로 구현하기 어렵다고 판단했다.

### 3.2 영상 다운로드 후 STT

영상을 내려받아 음성을 분리하고 STT를 수행한 뒤 변환된 텍스트를 분석하는 방법도 검토했다.

기술적으로는 가능하지만 비공식적인 영상·음성 수집 방식이 필요해 YouTube 정책 위반 가능성이 있다. 또한 화면에만 표시되는 장소 정보는 추출할 수 없으므로 제외했다.

### 3.3 Vertex AI Gemini 사용

Vertex AI는 공개 YouTube URL을 Gemini의 영상 입력으로 직접 전달하는 방식을 공식적으로 지원한다. 따라서 서버가 영상이나 음성을 직접 다운로드하지 않고 Google의 공식 API를 통해 분석할 수 있다.

실제 공개 YouTube Shorts URL을 Gemini 2.5 Flash Lite에 전달하여 다음 결과를 확인했다.

- YouTube Shorts URL 접근 성공
    
- 영상 입력 3,354토큰 처리
    
- 음성 입력 350토큰 처리
    
- 식당명과 지역 후보 반환
    
- 전체 입력·출력 3,927토큰
    
- 호출 비용 약 1원 미만
    

이를 통해 공개 Shorts URL의 영상과 음성에서 장소 정보를 추출할 수 있음을 확인했다.

현재는 단일 공개 Shorts를 대상으로 기술적 동작 여부를 확인한 단계이며, 다양한 영상에 대한 정확도와 비용은 구현 과정에서 추가로 측정한다.

## 4. 최종 선택안

MVP에서는 장소 기반 콘텐츠만 지원하며, 일정과 기간 기반 트리거는 제외한다.

저장 과정은 Spring이 정해진 순서로 모든 작업을 수행하는 단순 파이프라인이 아니라, 저장 에이전트가 분석 결과에 따라 필요한 도구와 다음 행동을 선택하는 구조로 구성한다.

```text
YouTube URL 입력
→ Spring에서 URL 검증 및 정규화
→ 저장 에이전트 실행
   ├─ YouTube Data API로 메타데이터 조회
   ├─ Vertex AI Gemini로 영상 내용 분석
   └─ 장소 후보에 따라 장소검색 API 호출
→ 저장 에이전트 판단
   ├─ 장소 확정 → 저장안 반환
   ├─ 후보 복수·불일치 → 재검색 또는 사용자 확인 요청
   └─ 장소 없음 → 장소 없는 저장안 반환
→ Spring에서 결과 검증
→ 검증된 장소가 있으면 위치 트리거 생성
→ DB 저장
```

저장 에이전트는 다음 결과를 반환한다.

- 처리 결과: `PLACE_RESOLVED`, `NEEDS_CONFIRMATION`, `NO_PLACE`
    
- 콘텐츠 요약
    
- 콘텐츠 카테고리
    
- 장소명과 지점명
    
- 장소 제공자의 식별자
    
- 주소와 좌표
    
- 사용자 확인이 필요한 경우 질문과 선택지
    

저장 에이전트는 장소검색 API를 도구로 사용해 장소 후보를 조회하고, 검색 결과가 불명확하면 검색어를 변경해 다시 조회하거나 사용자 확인을 요청한다.

Spring 서버는 에이전트가 반환한 결과의 형식과 필수 값을 검증한다. 장소가 확정된 경우에만 위치 트리거를 생성하고, 최종 DB 저장은 Spring의 서비스 계층에서 수행한다.

영상·음성·전체 자막은 직접 수집하거나 저장하지 않는다. 서비스 동작에 필요한 메타데이터, 짧은 요약, 검증된 장소 정보와 위치 트리거만 저장한다.

Elice ML API는 YouTube 영상 입력 경로에서는 사용하지 않는다. 저장 에이전트는 Vertex AI Gemini를 기반으로 동작하며, YouTube Data API와 장소검색 API를 도구로 사용한다.

## 5. 기획 및 인프라 변경 사항

### 변경 전

- Gemini를 이용한 영상 분석
    
- YouTube Data API를 이용한 메타데이터 조회
    
- 제공된 Elice 환경만으로 구현할 수 있다고 가정
    
- 장소와 일정 기반 트리거를 모두 고려
    

### 변경 후

- YouTube Data API와 Vertex AI 사용을 위한 별도 GCP 프로젝트 구성
    
- 영상 분석 및 저장 에이전트 모델로 Vertex AI Gemini 사용
    
- 저장 에이전트에 YouTube Data API와 장소검색 API를 도구로 제공
    
- Spring 애플리케이션에서 에이전트 결과 검증과 DB 저장 수행
    
- 로컬 환경에서는 ADC, 배포 환경에서는 서비스 계정 기반으로 Vertex AI 인증
    

DB에는 원본 영상·음성·전체 자막을 저장하지 않는다. URL, videoId, 메타데이터, 짧은 요약, 검증된 장소와 좌표, 위치 트리거만 저장한다.
