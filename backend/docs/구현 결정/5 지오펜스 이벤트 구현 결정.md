# 지오펜스 이벤트 → RecallExecution 구현 결정

## 범위

장소 이벤트를 받아 RecallExecution을 만들고 에이전트 실행을 시작하기까지. 에이전트의 판단 로직은 다음 단계에서 다룬다.

## 흐름

```
POST /api/location-events 수신
→ 세션 회원 + placeId로 Trigger 조회 (없으면 무시)
→ Trigger 행 잠금
→ 게이트 검사 (중복, 쿨다운, 오래된 이벤트)
→ RecallExecution을 PENDING으로 생성 후 커밋
→ 트랜잭션 밖에서 에이전트 실행 (동기)
→ 202 반환
```

게이트에서 걸려도 앱에는 202를 반환한다.

## 결정 사항

**이벤트 종류**

- Android는 DWELL, iOS는 ENTER만 등록한다. EXIT은 사용하지 않는다.
- Android DWELL 대기 시간은 30초로 시작한다. 서버 설정값으로 두고 `dwellDelayMs`로 내려준다.

**쿨다운**

- 트리거 단위로 최근 RecallExecution을 기준으로 검사한다. NO_ACTION으로 끝난 실행도 포함한다.
- 회원 단위 쿨다운은 알림 생성 단계에서 처리한다.
- 현재는 10분으로 설정 후, 추후에 확정할 예정

**오래된 이벤트**

- `eventOccurredAt`이 30분보다 오래된 이벤트는 실행하지 않는다.
- 장소만 재검증하는 API 추가 여부는 팀원과 논의 후 결정한다.

**동시성**

- 쿨다운 검사와 실행 생성 전에 Trigger 행을 비관적 락으로 잠근다.

**동기 처리**

- MVP는 동기로 처리한다. iOS가 10초 뒤 앱을 재워 요청이 끊겨도 서버는 실행을 마치고 결과를 FCM으로 전달한다.
- RecallExecution 생성은 짧은 트랜잭션으로 먼저 커밋하고, 에이전트는 트랜잭션 밖에서 실행한다.
- 앱은 끊긴 요청을 실패로 처리하지 않는다. 재시도는 같은 `triggerEventId`로 중복이 걸러진다.
- 비동기 전환 여부는 실행 시간 측정 후 결정한다.
