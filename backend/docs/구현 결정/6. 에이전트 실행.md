# 에이전트 실행 → Notification, FCM, openedAt 구현 결정

## 범위

에이전트가 PROPOSE를 낸 뒤 Notification을 만들고 FCM으로 전송하며, 사용자가 알림을 열었을 때 openedAt을 기록하기까지. 실제 에이전트 판단 로직은 임시 에이전트가 PROPOSE를 반환하도록 두고 별도로 구현한다.

## 흐름

```
이벤트 수신
→ 트랜잭션: Member 잠금 → 트리거 쿨다운·회원 쿨다운 검사
            → 걸리면 RecallExecution을 만들지 않음
            → RecallExecution PENDING 생성 → 커밋
→ 에이전트 실행 (PROPOSE)
→ 트랜잭션: RecallExecution COMPLETED/PROPOSE
            → Notification PENDING 생성 → 커밋
→ PENDING → SENDING 조건부 변경
→ 활성 Device의 FCM 토큰 조회
→ FCM 전송 (트랜잭션 밖)
→ 성공하면 SENT, 실패하면 FAILED
```

## 결정 사항

**회원 쿨다운**

- 알림이 아니라 에이전트 실행 기준으로 건다. 해당 회원의 최근 RecallExecution이 쿨다운 기간 안에 있으면 새 실행을 만들지 않는다.
- 연달아 지나친 장소는 비슷한 지역이므로, 먼저 실행된 에이전트가 주변 후보로 함께 검토한다고 보고 별도 실행을 하지 않는다.
- NO_ACTION으로 끝난 실행도 쿨다운에 포함한다.
- 쿨다운 기간은 설정값으로 둔다.

**잠금**

- 실행 생성 시 Trigger 대신 Member 행을 잠근다. 같은 회원의 서로 다른 트리거 이벤트도 함께 직렬화해야 회원 쿨다운이 지켜진다.

**알림 문구**

- 에이전트가 생성한다.
- 서버는 푸시 표시 길이와 페이로드 크기 제한에 맞춰 길이만 자른다.

**FCM 메시지**

- 알림 페이로드와 데이터 페이로드를 함께 보낸다.
- 알림 페이로드에는 제목과 본문을 넣어 앱이 꺼져 있어도 OS가 알림을 표시하게 한다.
- 데이터 페이로드에는 `notificationId`를 넣어 앱이 상세를 조회하고 중복 표시를 막게 한다.
- TTL은 30분으로 고정한다. FCM에 전송한 시점부터 적용되며, 그 사이 기기가 오프라인이면 30분이 지난 뒤에는 전달하지 않는다. Android와 iOS에 각각 설정한다.
- 데이터 페이로드의 `notificationId` 는 탭했을 때 상세를 여는 용도로 남기고, 중복 표시 방지는 `tag` 와 `apns-collapse-id` 로 한다.

**무효 토큰**

- FCM이 UNREGISTERED를 반환하면 Device의 토큰을 삭제한다.
- INVALID_ARGUMENT는 페이로드 오류일 때도 반환되므로 토큰을 삭제하지 않고 실패로만 기록한다.
- 삭제는 전송에 사용한 토큰 값이 그대로일 때만 수행하는 조건부 삭제로 한다. 그 사이 앱이 새 토큰을 올렸다면 지우지 않는다.
- 활성 Device나 토큰이 없으면 Notification을 FAILED로 기록한다.

**토큰 재발급**

- 앱은 FCM SDK가 새 토큰을 발급하면 `PUT /api/devices/fcm-token`으로 올린다.
- 앱은 시작할 때마다 현재 토큰을 올린다. 서버에서 토큰이 지워졌어도 다음 실행 때 복구된다.

**openedAt**

- `POST /api/notifications/{id}/open`은 세션 회원의 알림이고 아직 열리지 않은 경우에만 시각을 기록하는 조건부 UPDATE로 처리한다.
- 이미 열린 알림이면 기존 시각을 유지한다.
