### 배경

사용자가 저장한 장소가 여러 지역에 퍼져 있으면 모든 장소를 OS에 한꺼번에 등록할 수 없다. iOS는 앱당 최대 20개, Android는 앱과 기기 사용자당 최대 100개의 지오펜스를 등록할 수 있다. 특히 iOS에서는 저장 장소가 늘어나면 등록 대상을 선별해야 한다.

### 결정

**사용자의 저장 장소를 위치별로 묶은 지역 지오펜스와 개별 장소 지오펜스의 2단계**로 등록한다.

1. 서버는 현재 위치와 플랫폼을 받아, 등록 한도 안에서 가까운 개별 장소와 다른 지역의 장소 묶음을 골라 반환한다.
2. 앱은 받은 지역·장소 지오펜스를 OS에 등록한다.
3. 지역 지오펜스에 진입하거나 이탈하면 앱은 현재 위치로 등록 목록을 다시 조회하고, 필요한 장소 지오펜스로 교체한다. 지역 이벤트 자체는 꺼내기 에이전트를 실행하지 않는다.
4. 장소 지오펜스가 발동하면 앱은 장소 이벤트를 서버에 보낸다. 서버는 해당 사용자의 유효한 `Trigger`를 확인한 뒤 꺼내기 실행 여부를 결정한다.
5. 앱 시작·복귀 및 저장물 변경 시에도 등록 목록을 갱신한다. iOS에서는 큰 이동을 감지하는 위치 변경 이벤트를 등록 갱신의 보조 수단으로 검토한다.

같은 `Place`에 여러 `Trigger`가 연결되어 있어도 OS에는 장소 지오펜스를 하나만 등록한다. 장소 이벤트 한 건에서 서버가 관련 `Trigger`를 조회한다.

### 단계 전환 시 처리

지역 진입 후 장소 지오펜스를 등록할 때 사용자가 이미 해당 장소 반경 안에 있을 수 있다. 지오펜스는 경계를 넘을 때 이벤트를 보내므로, 이미 안에서 등록하면 새 진입 이벤트가 오지 않을 수 있다. 이를 플랫폼별로 처리한다.

- **Android:** 등록 시 `INITIAL_TRIGGER_DWELL`을 설정한다. 이미 반경 안에 있으면 OS가 체류 조건을 만족한 시점에 초기 체류 이벤트를 보낸다.
- **iOS:** 등록 직후 현재 영역 상태를 직접 조회한다. 안에 있다고 확인되면 앱이 장소 이벤트를 보낸다.

두 경우 모두 일반 장소 이벤트와 같은 검증 경로로 처리한다.

`triggerEventId`는 같은 이벤트의 재전송만 막는다. 재등록으로 생긴 이벤트는 새로운 ID를 가지므로, 같은 방문이 여러 번 전달되는 경우는 서버의 최근 실행·알림 검사로 제한한다.

iOS의 영역 상태 확인은 지원하는 OS 버전과 사용 중인 Core Location API에 맞춰 구현한다. 지오펜스 이벤트는 즉시 전달된다고 가정하지 않는다.

### 검토한 대안

| 대안                   | 판단                                     |
| -------------------- | -------------------------------------- |
| 모든 저장 장소를 항상 등록      | iOS 등록 한도에 빠르게 도달한다.                   |
| 현재 위치 근처의 장소만 등록     | 멀리 이동한 뒤 등록 목록을 바꿀 계기가 부족하다.           |
| 주기적으로 위치를 조회해 서버에 전송 | 주기적 위치 조회와 요청을 계속 수행해야 한다.             |
