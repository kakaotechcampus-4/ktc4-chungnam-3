## 배경

사용자가 저장한 장소가 여러 지역에 퍼져 있으면 모든 장소를 OS에 한꺼번에 등록할 수 없다. iOS는 앱당 최대 20개, Android는 앱과 기기 사용자당 최대 100개의 지오펜스를 등록할 수 있다. 특히 iOS에서는 저장 장소가 늘어나면 등록 대상을 선별해야 하고, 사용자가 다른 지역으로 이동하면 등록 목록을 바꿀 계기가 필요하다.

이전에는 저장 장소를 위치별로 묶은 지역 지오펜스와 개별 장소 지오펜스의 2단계로 등록하기로 했다. 그러나 저장한 지역이 많아지면 지역 지오펜스가 iOS 슬롯을 차지해 장소 지오펜스에 쓸 수 있는 슬롯이 줄고, 슬롯이 모자라 빠진 지역으로 이동하면 감지하지 못한다. 지역 묶음 계산과 경계 처리까지 필요해 구현도 크다.

## 결정

장소 지오펜스와 재조회용 지오펜스 하나를 등록하고, 두 플랫폼 모두 진입 이벤트로 장소 이벤트를 보낸다.

1. 서버는 현재 위치와 플랫폼을 받아, 이 회원의 트리거 장소 중 현재 위치에서 가까운 순으로 플랫폼 한도에서 한 자리를 뺀 만큼 골라 반환한다.
2. 서버는 재조회용 지오펜스 하나를 함께 반환한다. 중심은 요청한 현재 위치이고, 반경은 반환한 장소 중 가장 먼 장소까지의 거리에 여유를 더한 값이다. 설정한 최소 반경보다 작으면 최소 반경을 쓴다.
3. 앱은 장소 지오펜스와 재조회용 지오펜스를 OS에 등록한다.
4. 장소 지오펜스에 진입하면 앱은 장소 이벤트를 서버에 보낸다. 서버는 해당 회원의 유효한 Trigger를 확인한 뒤 꺼내기 실행 여부를 결정한다.
5. 재조회용 지오펜스에서 이탈하면 앱은 현재 위치로 등록 목록을 다시 조회한다. 재조회용 이벤트는 꺼내기 에이전트를 실행하지 않는다.
6. 앱 시작과 복귀, 저장물 변경 시에도 등록 목록을 다시 조회한다.

같은 Place에 여러 Trigger가 연결되어 있어도 OS에는 장소 지오펜스를 하나만 등록한다. 장소 이벤트 한 건에서 서버가 관련 Trigger를 조회한다.

재조회용 지오펜스의 반경을 반환한 장소 중 가장 먼 장소에 맞추므로, 원 안의 트리거 장소는 모두 등록된 상태가 된다. 등록되지 않은 장소는 원 밖에만 있고, 원을 벗어나는 순간 재조회가 일어난다.

## 등록 목록 API

`GET /api/geofences?latitude=…&longitude=…&platform=IOS|ANDROID`

```json
{
  "regions": [],
  "resync": {
    "geofenceId": "resync",
    "latitude": 0.0,
    "longitude": 0.0,
    "radiusMeters": 3000
  },
  "places": [
    {
      "geofenceId": "place:{placeId}",
      "placeId": "...",
      "latitude": 0.0,
      "longitude": 0.0,
      "radiusMeters": 150
    }
  ]
}
```

- places는 회원의 트리거 장소를 현재 위치 기준 가까운 순으로, 플랫폼 한도에서 한 자리를 뺀 개수까지 반환한다. 한도는 서버 설정값이며 기본값은 iOS 19, Android 99다.
- resync의 반경은 반환한 장소 중 가장 먼 장소까지의 거리에 여유를 더한 값이며, 설정한 최소 반경보다 작아지지 않는다.
- 같은 장소는 재조회해도 같은 geofenceId를 반환한다.
- 위치기반서비스 동의가 없는 회원은 places를 빈 목록으로, resync를 null로 반환한다.
- regions는 이후 지역 지오펜스가 필요해질 때를 위해 자리만 두고 빈 배열로 반환한다.

## 이벤트 종류

- 두 플랫폼 모두 장소 이벤트는 ENTER로 보낸다.
- 장소 지오펜스의 EXIT는 서버에 보내지 않고, 앱 안의 상태를 초기화하는 데만 쓴다.
- 재조회용 지오펜스는 EXIT만 쓴다.

Android의 진입 이벤트는 iOS와 달리 머문 시간 조건이 없어, 걸어서 또는 차로 지나가기만 해도 발생할 수 있다. 회원 쿨다운은 NO_ACTION을 포함한 모든 실행을 세므로, 지나가는 이벤트가 쿨다운을 소모해 이후의 실제 방문이 막힐 수 있다. MVP에서는 이를 감수하고 실기기 측정으로 영향을 확인한다.

triggerEventId는 같은 이벤트의 재전송만 막는다. 같은 방문이 여러 번 전달되는 경우는 서버의 회원 쿨다운으로 제한한다.

## 등록 시 이미 안에 있는 경우

지오펜스는 경계를 넘을 때 이벤트를 보내므로, 이미 반경 안에서 등록하면 진입 이벤트가 오지 않을 수 있다. expo-location은 이를 위한 초기 트리거 설정을 제공하지 않으므로 앱이 직접 판단한다.

- 등록 직후 현재 위치를 받아 각 장소 지오펜스와의 거리를 계산한다.
- 반경 안이고, 그 장소를 아직 안에 있다고 보고하지 않았다면 장소 이벤트를 보낸다.

두 플랫폼이 같은 방식으로 처리하며, 일반 장소 이벤트와 같은 검증 경로를 탄다.

## 같은 장소의 반복 보고 방지

앱을 열 때마다 동기화하면서 이미 안에 있는지 판단하면, 저장 장소가 집 근처에 있을 때 앱을 열 때마다 이벤트가 간다. 이를 막기 위해 앱은 장소별로 안과 밖 상태를 기억한다.

- 장소 이벤트를 보낸 장소는 안에 있음으로 기록한다.
- 안에 있음으로 기록된 장소는 이벤트를 다시 보내지 않는다.
- 그 장소 지오펜스의 EXIT를 받으면 밖으로 바꾼다. 다음 진입부터 다시 보낸다.

## 검토한 대안

|대안|판단|
|---|---|
|모든 저장 장소를 항상 등록|iOS 등록 한도에 빠르게 도달한다.|
|지역 지오펜스와 장소 지오펜스의 2단계 등록|저장한 지역이 많으면 지역 지오펜스가 슬롯을 차지하고, 빠진 지역으로의 이동은 감지하지 못한다. 묶음 계산과 경계 처리로 구현도 크다.|
|iOS 큰 위치 변경 감지로 재조회|슬롯을 쓰지 않지만 expo-location에서 이 기능을 그대로 쓸 수 있는지 확인되지 않았고, Android에는 같은 기능이 없어 플랫폼별로 따로 구현해야 한다.|
|Android만 네이티브로 DWELL 사용|지나가는 이벤트를 줄일 수 있지만, 30초 대기로는 걸어서 지나가는 경우를 거의 거르지 못하고 네이티브 모듈 구현 비용이 크다.|
|주기적으로 위치를 조회해 서버에 전송|iOS는 백그라운드 주기 실행을 보장하지 않고, 위치 조회와 요청을 계속 수행해야 한다.|

## 결과와 한계

- 두 플랫폼이 expo-location 하나로 같은 방식으로 동작한다.
- 저장한 지역의 수와 관계없이, 재조회용 지오펜스를 벗어나면 새 위치 기준으로 등록 목록이 바뀐다.
- 서버는 지역 묶음 계산 없이 가까운 장소를 고르고 재조회 반경 하나만 계산하면 된다.
- 재조회용 지오펜스가 슬롯 하나를 차지해 장소 지오펜스는 iOS 19개, Android 99개까지 등록된다.
- Android에서는 지나가는 이벤트가 늘어날 수 있다.
- 지오펜스가 앱이 꺼진 상태에서 동작하려면 위치 권한을 항상 허용으로 받아야 한다.
- Android는 기기 재부팅, 앱 재설치, 앱 데이터 삭제, Google Play 서비스 데이터 삭제 후 등록된 지오펜스를 시스템이 복구하지 못한다. expo-location이 재부팅 후 자동으로 다시 등록하는지는 확인되지 않았으며, 확인 전까지는 앱을 다시 열 때의 동기화로 복구한다.

## 프론트 구현 지침

### 의존성과 권한

- expo-location의 지오펜스는 백그라운드 작업 등록에 expo-task-manager가 필요하다. 의존성에 추가하고, 지오펜스 작업은 앱 최상위에서 정의한다.
- 위치 권한은 항상 허용으로 요청한다.
- 알림 권한을 요청하고 FCM 토큰을 `PUT /api/devices/fcm-token`으로 등록한다.

### 등록 목록 동기화

- 현재 위치와 플랫폼으로 `GET /api/geofences`를 호출한다.
- places와 resync를 함께 등록한다. expo-location은 같은 작업 이름으로 다시 등록하면 지역 목록 전체가 교체되므로, 받은 목록을 그대로 넘긴다.
- 장소 지오펜스는 진입과 이탈 알림을 모두 켠다. 진입은 서버 보고에, 이탈은 앱 안의 상태 초기화에 쓴다.
- 재조회용 지오펜스는 이탈 알림만 켠다.
- geofenceId와 placeId의 대응을 기기에 저장해, 이벤트가 오면 placeId를 찾을 수 있게 한다.
- 등록 직후 현재 위치와 각 장소의 거리를 계산해, 반경 안이고 아직 안에 있음으로 기록되지 않은 장소는 장소 이벤트를 보낸다.
- 목록에서 빠진 장소의 안과 밖 상태 기록은 지운다.

### 지오펜스 이벤트 처리

- 장소 지오펜스 진입: 그 장소가 안에 있음으로 기록되어 있지 않으면 장소 이벤트를 보내고 안에 있음으로 기록한다.
- 장소 지오펜스 이탈: 그 장소를 밖으로 바꾼다. 서버에는 보내지 않는다.
- 재조회용 지오펜스 이탈: 등록 목록을 다시 동기화한다.

### 재조회

- 앱 시작과 포그라운드 복귀 시 동기화한다.
- 저장과 삭제가 끝나면 동기화한다.
- 재조회용 지오펜스에서 이탈하면 동기화한다.

### 장소 이벤트 전송

- `POST /api/location-events`로 보낸다.
    - placeId는 geofenceId 대응표에서 찾는다.
    - triggerEventId는 보낼 이벤트 하나마다 새 UUID를 만든다.
    - eventType은 ENTER.
    - eventOccurredAt은 이벤트가 발생한 시각.
    - 위치는 위도, 경도, 정확도, 측정 시각 네 값을 모두 알 때만 함께 보낸다.
- 응답은 항상 202이며 앱은 결과로 분기하지 않는다. 결과는 FCM 알림으로 온다.
- iOS는 백그라운드에서 깨어난 뒤 실행 시간이 짧으므로 이벤트를 받자마자 보낸다.
- 전송이 실패하면 같은 triggerEventId로 재시도한다. 사용자에게 오류를 띄우지 않는다.

### 해제

- 로그아웃하거나 위치기반서비스 동의를 철회하면 등록된 지오펜스를 모두 해제하고 안과 밖 상태 기록을 지운다.
