# 핵심 도메인

## 사용자 - Member

서비스를 사용하는 사용자를 관리합니다.  
개인 저장물을 소유하며, 트리거와 꺼내기 실행 및 알림은 개인 저장물을 통해 사용자와 연결됩니다.

## 콘텐츠 - Content

사용자가 공유한 YouTube 콘텐츠와 분석 결과를 관리합니다.  
동일한 영상은 `videoId`를 기준으로 멱등하게 처리하며, 여러 사용자가 저장해도 하나의 콘텐츠만 생성합니다.

## 개인 저장물 - PersonalSave

사용자가 콘텐츠를 저장한 관계를 관리합니다.  
사용자별 저장 상태와 저장 시각, 공용 제공 동의 여부와 동의 시각을 관리합니다.  
사용자는 자신의 공용 제공 동의를 철회할 수 있으며, 동일한 사용자가 같은 콘텐츠를 중복 저장하지 않도록 관리합니다.

## 공용 풀 - PublicPool

꺼내기 에이전트가 보충 후보로 사용할 수 있는 콘텐츠를 관리합니다.  
하나의 콘텐츠는 공용 풀에 최대 한 번만 등록되며, 등록한 사용자 정보는 직접 저장하지 않습니다.  
공용 제공 여부는 `PersonalSave`에서 관리하며, 동의 상태인 개인 저장물이 하나 이상 존재하는 동안 공용 풀을 유지합니다.  
모든 사용자가 공용 제공을 철회하면 해당 콘텐츠를 공용 풀에서 비활성화하거나 삭제합니다. 공용 풀은 트리거를 생성하지 않습니다.

## 장소 - Place

검증이 완료된 실제 장소를 관리합니다.  
장소명, 주소, 좌표 및 외부 장소 식별자 등을 저장하며, 검증되지 않은 장소 후보는 `Place`로 저장하지 않습니다.

## 콘텐츠와 장소 연결 - ContentPlace

콘텐츠에서 특정 장소가 어떻게 소개되었는지를 관리합니다.  
`Content`와 `Place`의 다대다 관계를 연결하며, 영상에서 해당 장소를 소개한 내용인 `description`, 제안 순서인 `suggestedOrder`, 추출 신뢰도 등을 저장합니다.  
검증에 성공한 장소만 `ContentPlace`로 생성하며, 꺼내기 에이전트는 이 정보를 장소를 제안하는 이유와 콘텐츠 맥락을 구성하는 데 사용합니다.

## 트리거 - Trigger

개인 저장물을 다시 꺼낼 위치 조건을 관리합니다.  
`PersonalSave`와 `ContentPlace`를 연결하며 지오펜스 반경과 활성 상태를 관리합니다.  
하나의 콘텐츠에 여러 장소가 있으면 장소별로 트리거를 생성할 수 있습니다.

## 꺼내기 실행 - RecallExecution

트리거로 시작된 꺼내기 에이전트의 실행을 관리합니다.  
검토한 후보, 도구 호출, 판단 과정과 최종 결과인 `PROPOSE` 또는 `NO_ACTION`을 기록합니다.

## 알림 - Notification

사용자에게 전달한 제안과 전송 결과를 관리합니다.  
중복 알림과 최근 알림 여부를 검사하는 근거로 사용하며, `NO_ACTION`인 실행에는 알림이 생성되지 않습니다.

# 보조 저장 구조

## 장소 후보 검증 기록 - PlaceCandidateLog

Gemini가 추출한 장소 후보와 장소 검색 결과를 기록합니다.  
검증 성공과 실패를 모두 기록하여 추출 오류, 검색 실패, 모호한 검색 결과 및 외부 API 오류를 구분합니다.  
분석 실행 식별자, 모델 버전, 프롬프트 버전, 추출된 장소명, 검색 질의, 검증 결과와 실패 이유를 기록하며 프롬프트와 장소 검증 과정의 개선에 활용합니다.  
운영과 분석을 위한 기록이므로 핵심 도메인에는 포함하지 않습니다.

# 주요 관계

```text
Member 1:N PersonalSave
Content 1:N PersonalSave
Content 1:0..1 PublicPool
Content 1:N ContentPlace
Place 1:N ContentPlace
PersonalSave 1:N Trigger
ContentPlace 1:N Trigger
Trigger 1:N RecallExecution
RecallExecution 0..1 Notification
```
