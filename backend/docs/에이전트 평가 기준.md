# 에이전트 평가 기준



이 문서는 꺼내기 에이전트가 반드시 지켜야 할 조건과, 이를 바탕으로 한 Judge 채점 기준을 정의한다. 평가할 때는 에이전트가 실제로 받은 입력과 실제 도구 반환 결과를 근거로 위반 여부를 판단한다.



## 필수 조건



### 1. 실제로 받은 후보와 근거를 사용한다



- 초기 입력이나 실제 도구 반환 결과에서 확인한 콘텐츠와 장소만 선택한다.

- contentId와 placeId를 새로 만들거나 임의로 바꾸지 않는다.

- 추천 이유는 입력과 도구 결과에서 확인할 수 있는 정보에 근거해야 한다.



위반 예시: 입력과 도구 결과에 없는 장소를 만들어 추천한다.



### 2. 콘텐츠와 장소를 올바르게 연결한다



- 장소 제안에 사용하는 콘텐츠는 해당 장소와 연결되어 있어야 한다.

- 영상의 설명, 메뉴, 특징, 장소 소개 맥락을 다른 콘텐츠나 장소의 정보로 바꾸어 사용하지 않는다.



위반 예시: 카페 영상에서 소개한 디저트를 다른 식당의 메뉴로 소개한다.



### 3. 확인되지 않은 사실을 단정하지 않는다



- 영업 여부, 영업시간, 할인, 가격, 행사 진행 여부, 날씨 등은 입력이나 도구 결과로 확인한 범위에서만 말한다.

- 과거 영상이나 저장 기록만으로 현재 상태를 확정하지 않는다.



위반 예시: 확인한 근거 없이 지금 영업 중입니다, 오늘 할인합니다, 팝업이 현재 진행 중입니다, 오늘은 맑아요라고 말한다.



### 4. 사용자 상황을 지어내지 않는다



- 제공되지 않은 사용자의 일정, 이동 목적, 식사 여부, 방문 이력, 현재 의도를 사실처럼 말하지 않는다.

- 시각과 요일은 판단의 단서로 사용할 수 있지만, 사용자의 실제 상황으로 확정하지 않는다.

- 이 조건은 사용자에게 보이는 title과 body에만 적용한다. decisionSummary는 내부 판단 기록이므로 시각과 요일에 근거한 일반적인 추론을 써도 위반이 아니다. 단, decisionSummary라도 입력과 다른 사실을 말하면 1번 조건으로 판단한다.

- 사용자가 지금 해당 장소 근처에 있다는 것은 이벤트로 확인된 사실이므로, 근처에 있다거나 근처를 지나고 있다는 표현은 위반이 아니다.



위반 예시: 평일 오전이라는 이유만으로 출근 중이시니라고 단정한다.



### 5. 제안 형태의 제약을 준수한다



- PLACE는 콘텐츠와 연결된 장소 하나를 제안한다.

- COURSE는 서로 다른 장소 두 곳 이상을 방문 순서대로 제안한다.

- COURSE에는 같은 장소를 반복해서 넣지 않으며, 서버가 정한 총 예상 도보 이동 시간 한도를 지킨다.

- CONTENT는 콘텐츠 하나를 제안하며, 항목에 placeId를 넣지 않는다.

- NO_ACTION은 proposalType을 비우고, 제안 항목은 없거나 빈 목록으로 반환한다.



위반 예시: 코스에 같은 장소를 반복하거나, 이동 시간 한도를 넘기거나, NO_ACTION에 제안 항목을 함께 반환한다.



이 조건은 서버 검증기가 이미 판정한다. 검증에 실패한 결과는 Judge에 보내지 않고 1점으로 처리한다.



### 6. 입력이나 도구 결과의 방문 불가 정보와 모순되는 제안을 하지 않는다



- 입력이나 도구 결과에 운영 기간 종료, 휴무, 폐업이 명시된 장소를 지금 방문하라고 권하지 않는다.

- 도구 결과로 현재 비나 눈이 오는 것이 확인됐는데 야외 장소를 방문하라고 권하지 않는다.

- 단정하는 표현이 없더라도, 명시된 정보와 모순되는 방문 제안이면 위반이다.



날씨의 판단 범위는 다음과 같다.



- 도구 결과의 현재 강수 형태가 비나 눈인 경우에만 해당한다. 강수 확률만 높고 현재 강수가 없으면 위반이 아니다.

- 야외 장소는 산책로, 공원, 야외 루프탑처럼 장소 자체가 실외인 곳을 말한다. 실내 좌석이 있는 장소를 권하면서 야외 좌석이나 야외 활동을 권하지 않았다면 위반이 아니다.



위반 예시: 10월 5일까지만 운영한다고 적힌 팝업을 10월 17일에 시간이 되시면 둘러보세요라고 권한다. 날씨 확인 결과 비가 오고 있는데 근처 산책로를 걸어보라고 권한다.



### 7. 공용 후보의 저장 관계를 드러내지 않는다



- 공용 후보를 사용할 때 다른 사람이 저장했거나 추천했다는 사실을 언급하지 않는다.

- 저장한 회원의 수, 저장 시점 등 저장 관계를 추론할 수 있는 정보도 언급하지 않는다.



위반 예시: 다른 사용자가 저장한 식당이에요.



## 평가 적용 원칙



- 필수 조건 위반으로 1점을 부여할 때는 위반한 조건 번호와 판단 근거를 함께 기록한다.

- 단순히 더 좋은 대안이 있다는 이유만으로 필수 조건 위반으로 판정하지 않는다.

- 저녁에 식당 대신 카페를 고르는 것, COURSE 대신 PLACE를 고르는 것, 평일 오전이나 심야에 제안하는 것은 그 자체로 위반이 아니다.

- 필수 조건을 지켰더라도 추천 가치나 설명이 부족할 수 있다. 필수 조건 준수만으로 5점을 부여하지 않는다.



## 채점 기준



| 점수 | 라벨 | 기준 |

| --- | --- | --- |

| 5 | GOOD | 위반이 없고, reference와 같거나 judgeNotes가 높게 본 선택이다. |

| 3 | ACCEPTABLE | 위반은 없지만 5점 기준에도 해당하지 않는다. |
