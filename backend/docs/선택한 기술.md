# 언어
**백엔드 - Java, Spring**
백엔드는 Java와 Spring Boot를 이용하여 구성할 계획입니다. 
백엔드 담당인 저는, 파이썬과 자바 둘 모두 자신있는 언어이지만, 자바는 프레임워크까지 다루면서 프로젝트를 진행했던 경험이 있고 파이썬으로는 fastAPI등 프레임워크를 이용했던 경험이 없습니다. 또 한, 다른 백단의 흐름을 담당하는 팀원들이 파이썬 보단 자바에 익숙한 상황을 고려해 봤을때 백엔드까지 파이썬으로 구현시 팀의 학습과 코드 검증 부담이 커지지만, 그에 반해 기능상 얻는 이점이 명확치 않은것 같습니다.

**꺼내기 에이전트 - 미정**
꺼내기 에이전트는 현재 기획상, Java와 Python 모두 구현 가능해보입니다. 담당자인 저는 두 언어는 모두 익숙한 상황이지만 파이썬은 프레임워크를 학습해 본 경험이 없습니다. 
자바를 선택하게 된다면, 익숙한 언어에서 익숙한 프레임워크, 또한 백엔드 서버에 직접 붙는 내부 모듈형식으로 구현하여 별도 통신과 배포가 필요치 않을 수 있습니다. 반면 파이썬으로 구현 시, 가설 변경 도구 호출등 흐름을 더 확장시키는 과정에서 더 많은 파이썬 기반 오픈소스를 활용할 여지가 있을것 같습니다. 
따라서 아직 꺼내기 에이전트의 언어와 분리여부는 미정으로 둘려고 합니다.
이에대한 멘토님의 생각이 궁금합니다!

# DB - PostgreSQL

사용자, 저장 콘텐츠, 장소, 알림 이력 등이 서로 참조되므로, 관계와 데이터 정합성을 관리하기 적합한 PostgreSQL을 선택했습니다.

꺼내기 에이전트는 현재 위치 주변의 장소를 조회하는 공간 검색과, 요약을 바탕으로 유사한 저장물을 찾는 벡터 검색을 사용합니다. PostgreSQL은 PostGIS와 pgvector 확장을 지원하므로 일반 데이터와 위치·임베딩 데이터를 하나의 데이터베이스에서 관리할 수 있습니다.

MVP에서는 별도의 공간·벡터 데이터베이스를 두지 않을 예정입니다. 배포와 운영이 단순하고 데이터 정합성을 관리하기 쉽기 때문입니다. 이후 데이터 규모와 검색 부하를 측정한 뒤 별도 검색 인프라가 필요한지 판단할 예정입니다.
