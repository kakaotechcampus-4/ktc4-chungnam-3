# 꺼내기 에이전트 MVP 완결 기준

에이전트 개선 작업이 끝없이 늘어나지 않도록, MVP에서 에이전트가 완결됐다고 보는 기준과 거기까지 남은 일을 정한다. 이 기준을 넘으면 에이전트 작업을 멈추고 서비스 연결로 넘어간다.

## 배경

에이전트 구조는 제출 필수 조건이다.

기존 도구는 후보 검색, 상세 조회, 거리 조회였다. 프롬프트 v3에서 도구를 켠 실행과 끈 실행을 같은 골든셋으로 비교했다.

|실행|BAD|AGENT\_FAILED|시간 중앙값|실행당 토큰|
|-|-:|-:|-:|-:|
|v1 도구 OFF 기준선|5 / 72|1.4%|7.7초|1,840|
|v2 도구 ON|4 / 72|0%|8.1초|3,971|
|v3 도구 ON|1 / 72|0%|8.3초|4,069|
|v3 도구 OFF|0 / 72|0%|7.0초|2,033|

holdout 6장면은 v3 도구 ON과 OFF 모두 BAD 0이었다.

도구를 켜도 판단이 나아지지 않았다. 기존 도구는 모두 서버가 첫 입력에 이미 준 정보를 조금 더 보여주는 것이라, 에이전트가 도구를 쓸 이유가 거의 없었다. 그래서 도구의 역할을 후보를 고르는 것에서, 고른 후보가 지금 방문하기 적절한지 확인하고 대안을 찾는 것으로 바꾼다.

## 에이전트 흐름

잠정 제안 → 방문 조건 확인 → 부적합하면 대안 검색 → 최종 제안 또는 침묵

* 방문 가능한 제안을 만드는 것까지 에이전트의 책임으로 프롬프트에 명시한다.
* 첫 입력만으로 판단이 충분하면 도구 없이 결정할 수 있다.

## 도구

### 1\. 방문 조건 확인

잠정으로 고른 장소가 지금 방문하기 적절한지 확인한다. 항목마다 출처와 기준 시각을 함께 돌려준다.

|항목|출처|판단이 바뀌는 상황|
|-|-|-|
|운영 기간, 휴무, 예약 조건|저장된 전체 설명과 장소 소개 맥락|기간이 지났거나 오늘 휴무면 제외|
|날씨|기상청 단기예보|야외 장소인데 비나 눈이 오면 제외|
|최근 제안과 반응|알림 기록|최근 제안했는데 열어보지 않았으면 다른 후보|

* 저장된 설명은 저장 시점의 정보라는 것을 기준 시각으로 함께 알린다.
* 카카오 검색에 장소가 나온다는 사실만으로 현재 영업 중이라고 판단하지 않는다.

### 2\. 조건별 대안 검색

기존 후보 검색을 보강한다.

* 목적, 반경, 개인과 공용 범위로 검색한다.
* 이미 입력이나 이전 검색에서 본 후보는 제외한다.

기존 상세 조회와 거리 조회 도구는 제거한다. 상세 조회의 역할은 방문 조건 확인에 흡수되고, 거리는 첫 입력과 서버 검증으로 충분하다.

## 평가 세트

### 회귀 세트

기존 골든셋 30장면을 그대로 쓴다. 새 구조가 기본 판단을 망가뜨리지 않는지 확인하고, v1부터 v3까지의 결과와 비교를 이어간다.

### 도구 세트

방문 조건 확인과 대안 검색의 결과가 판단을 바꾸는 장면을 새로 만든다. 같은 구성에서 조건 하나만 바꾼 쌍으로 만든다.

|확인 항목|쌍|기대|
|-|-|-|
|날씨|루프탑, 산책로, 테라스에 맑음과 비|비 오면 실내 대안이나 침묵|
|휴무, 운영 기간|설명 뒤쪽에 오늘 휴무와 내일 휴무|오늘 휴무면 제외|
|최근 제안|최근 제안 후 열어보지 않음과 이력 없음|열어보지 않았으면 다른 후보|
|대안 검색|식사 시간에 첫 입력엔 카페만 있고, 근처에 식당 있음과 없음|있으면 찾아서 제안|

도구가 필요 없는 장면도 몇 개 넣는다. 실내 장소 하나뿐인 장면처럼, 도구를 부르면 불필요한 호출이 되는 경우다.

평가에서는 날씨를 장면마다 고정값으로 주는 가짜 클라이언트를 쓰고, 최근 제안 이력은 시드할 때 알림 기록으로 함께 넣는다.

## 평가 기준 문서 변경

필수 조건 6을 확장한다. 도구 결과로 비나 눈이 확인된 상황에서 야외 장소를 방문하라고 권하는 것도 위반으로 본다. 최근 제안을 반복하는 것은 판단의 문제이므로 필수 조건으로 두지 않는다.

## 완결 기준

판정은 LLM Judge가 에이전트 평가 기준 문서로 채점하고, 3점 이상이면 통과로 본다.

1. **회귀 세트 tune**: 24장면 3회, 72건 중 BAD 1건 이하, AGENT\_FAILED 2% 이하.
2. **회귀 세트 holdout**: 6장면 1회에서 BAD 없음.
3. **도구 세트**: 3회 실행에서

   * BAD 1건 이하
   * 확인이 필요한 장면에서 방문 조건 확인을 부른 비율 80% 이상
4. **비용 기록**: 실행당 토큰과 시간 중앙값, 도구 불필요 장면의 불필요 호출 비율을 기록한다. 임계값은 두지 않는다.
5. **결과 기록**: 기준선부터 최종까지의 숫자를 표 한 장으로 남긴다.
